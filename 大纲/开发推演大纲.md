# AI 个人财务 CFO：开发能力推演大纲

## 一、这份推演解决什么问题

在 `learn` 工作空间中，学习分成两条彼此配合、职责不同的路线。


| 学习线   | 项目                | 主要目的                                       |
| ----- | ----------------- | ------------------------------------------ |
| 知识输入线 | `ai-finance-cfo/` | 学习技术术语、框架 API、代码模块、项目细节和完整参考实现             |
| 能力输出线 | `try-ai-cfo/`     | 结合 AI Tutor 模拟开发流程，练习需求判断、方案拆解、编码、调试、验证和复盘 |


两条线不能混成同一种学习方式。

在 `ai-finance-cfo/` 中，可以按照课程逐步学习：

- JavaScript、TypeScript、React 和 Next.js。
- HTTP、API、SQLite、Drizzle 和 Zod。
- 财务计算、测试、AI、CSV 和产品化细节。
- 一个完整项目为什么这样组织、每个模块如何实现。

在 `try-ai-cfo/` 中，不再重复听一遍相同课程，也不照着参考项目重写代码。AI Tutor 会给出相对真实、没有步骤答案的开发任务，由学习者主动完成：

```txt
理解需求
  ↓
提出问题
  ↓
划定范围
  ↓
设计数据流
  ↓
编写第一版
  ↓
运行并收集证据
  ↓
调试和修改
  ↓
验收、讲解与迁移
```

这份大纲只负责能力输出线。

核心目标不是再做一个完整的 CFO，而是：

> 使用已经学过的知识，独立完成少量但完整的纵向闭环，把“看得懂”转化为“能开发”。



## 二、双线学习的配合规则



### 1. 先在知识线学习，再在推演线调用

核心技术必须先在 `ai-finance-cfo/` 中学习，再进入 `try-ai-cfo/` 的正式推演。

例如：

- 学过 React 状态和表单后，才推演假数据账户管理。
- 学过 API、Zod、Drizzle 和 SQLite 后，才推演持久化 CRUD。
- 学过纯函数、`decimal.js` 和 Vitest 后，才推演确定性财务计算。
- 学过模型 API、结构化输出和 AI 职责边界后，才推演 AI 问答闭环。

Tutor 不在推演过程中首次系统教授一项尚未学过的核心技术。

如果任务需要的核心知识尚未解锁：

1. 暂停该关卡。
2. 回到知识线完成对应课程。
3. 确认自己能解释基础概念。
4. 再回到推演线继续。



### 2. 文档存在不等于知识已经解锁

判断是否解锁，以实际学习结果为准，不以课程文件是否已经存在为准。

一项知识至少满足以下条件，才视为已经学过：

- 完成对应课程的阅读和练习。
- 能说出它解决什么问题。
- 能看懂知识线中的基础实现。
- 能完成课程要求的最小验收。



### 3. 三种信息必须分开

推演中会同时出现三种信息：


| 信息     | 含义                                       |
| ------ | ---------------------------------------- |
| 完整产品蓝图 | 一个完整 AI 个人财务 CFO 最终可能包含什么，以及系统各层如何配合     |
| 知识线进度  | `ai-finance-cfo` 已经实际学完哪些技术，决定哪些推演关卡可以解锁 |
| 推演线状态  | `try-ai-cfo` 中由学习者独立完成了什么、验证了什么、还缺什么     |


例如：

- 完整蓝图包含 CSV、负债和场景模拟，不代表本轮必须编码这些功能。
- 知识线已经实现账户 API，不代表推演线的账户 API 已经完成。
- 第 20、21 课文档已经准备好，不代表财务计算关卡已经解锁。



### 4. 原项目只是知识来源和参考答案

`ai-finance-cfo/` 不再是推演任务的工作目录，也不用于替学习者完成当前关卡。

只有两种情况下可以查看其对应实现：

1. 当前闭环已经独立完成，并保存了验证证据，准备进行对照复盘。
2. 分级提示已经升到第五级，仍然无法推进，明确需要参考实现。

对照时只记录：

- 两种实现的结构差异。
- 自己遗漏的状态或边界。
- 参考方案解决了什么问题。
- 自己下一次会怎样调整。

不要把参考项目的代码直接复制进 `try-ai-cfo/`。

## 三、本轮推演范围



### 1. 完整产品蓝图仍然保留

系统思考仍然以完整 AI 个人财务 CFO 为背景，包括：

- 账户、流水、负债和目标。
- 确定性财务计算。
- AI 财务问答。
- CSV 导入。
- 财务仪表盘。
- What-if 场景模拟。

## 四、完整系统地图

系统地图用于帮助思考完整产品，不代表每一条链路都要在本轮实现。

### 1. 数据管理链路

```txt
React 页面和表单
  ↓
fetch 请求
  ↓
Next.js Route Handler
  ↓
Zod 校验
  ↓
service 业务层
  ↓
Drizzle ORM
  ↓
SQLite
```

各层的基本职责：


| 层级               | 负责什么           | 不负责什么    |
| ---------------- | -------------- | -------- |
| 页面和组件            | 收集输入、展示状态、触发操作 | 直接读写数据库  |
| Route Handler    | 处理 HTTP 请求和响应  | 堆放全部业务规则 |
| Zod schema       | 校验运行时输入        | 执行业务计算   |
| service          | 组织业务规则和数据访问    | 负责页面交互   |
| Drizzle 和 SQLite | 持久化和查询数据       | 决定页面如何展示 |




### 2. 财务计算链路

```txt
SQLite 中的账户、流水、负债和目标
  ↓
service 查询并整理数据
  ↓
确定性财务计算函数
  ↓
公式、输入、中间步骤和结果
  ↓
计算历史
  ↓
页面或 API 展示
```

核心边界：

> service 负责取得数据，计算引擎负责根据明确输入产生确定结果。

财务计算函数不应直接依赖：

- React state。
- 网络请求。
- 数据库连接。
- 当前页面。
- 模型输出。



### 3. AI 财务问答链路

```txt
用户自然语言问题
  ↓
AI 解析结构化意图
  ↓
Zod 校验 AI 输出
  ↓
读取所需财务数据
  ↓
确定性计算引擎执行计算
  ↓
保存或展示计算依据
  ↓
AI 组织自然语言解释
  ↓
页面展示回答
```

贯穿系统的原则：

> AI 负责理解语言和组织表达，财务结果必须由确定性代码计算。



### 4. 外部数据扩展链路

未来加入 CSV 时，可以沿下面的链路扩展：

```txt
外部文件
  ↓
解析和字段映射
  ↓
标准化
  ↓
Zod 校验
  ↓
去重和业务规则
  ↓
保存
  ↓
复用已有计算与展示能力
```

本轮只设计它与现有层级的关系，不实现该链路。

## 五、AI Tutor 工作协议



### 1. 角色分工


| 角色或工具          | 主要职责                                     |
| -------------- | ---------------------------------------- |
| Cursor 和本地项目   | 阅读任务、形成方案、编写代码、运行项目、检查 Network、终端、数据库和测试 |
| Codex/Deepseek | 检查解锁条件、发布任务、分级提示、审查代码和证据、追问理由、生成测试与变体    |
| 学习者            | 拆解需求、选择方案、完成第一版、收集证据并作出最终验收              |
| Markdown       | 保存判断、验收标准、问题证据、实现说明和复盘                   |


Codex/Deepseek 是教练，不替代学习者首次分析、首次实现和首次验证。

### 2. 每关固定循环

```txt
Tutor 检查解锁条件
  ↓
只发布情境、需求、约束和验收标准
  ↓
学习者写初始判断
  ↓
在 try-ai-cfo 独立实现 20～30 分钟
  ↓
卡住时携带证据请求分级提示
  ↓
学习者先自行运行和验证
  ↓
Codex/Deepseek 审查代码、证据和设计理由
  ↓
学习者完成修改、讲解和变体
  ↓
次日复现核心结构
```



### 3. 关卡记录模板

每一关使用以下结构：

```md
# 第 X 关：关卡名称

## 任务

## 我的初始判断

## 验收标准

## 遇到的问题与证据

## 最终实现说明

## 复盘与变体
```

初始判断只写足以指导当前行动的内容，不抄写大纲，也不提前写完整答案。

### 4. 分级提示

```txt
一级：指出下一步检查方向
二级：指出相关文件或概念
三级：提供伪代码
四级：提供最小代码片段
五级：提供参考实现或允许对照知识线项目
```

尽量停在能让学习者重新推进的最低一级。

提问时应提供：

```txt
目标：
期望结果：
实际现象：
已经检查：
当前判断：
希望获得的提示级别：
```



### 5. 审查和调试规则

学习者完成第一版并运行后，Codex 再检查：

- 正确性。
- 数据流。
- 边界和失败状态。
- 类型与运行时校验。
- 安全性。
- 可读性。

每轮优先指出最多三个最重要的问题，不直接重写整个实现。

遇到故障时遵循：

```txt
稳定复现
  ↓
记录期望和实际结果
  ↓
收集报错、请求、响应和数据证据
  ↓
提出按可能性排序的假设
  ↓
一次验证一个关键假设
  ↓
最小修改
  ↓
回归相邻功能
```



### 6. 五维能力验收


| 维度  | 验收问题               |
| --- | ------------------ |
| 解释  | 能否不看代码说清数据流和设计理由？  |
| 复现  | 能否从空白写出核心骨架？       |
| 修改  | 更换字段或增加状态后能否自行调整？  |
| 调试  | 出错时能否先收集证据并判断问题层级？ |
| 迁移  | 能否完成一个相似但不相同的需求？   |


判断标准：

- 只满足“解释”，仍处于理解阶段。
- 满足“解释、复现、修改”，达到基础可用。
- 再满足“调试”，接近初级工程交付能力。
- 五项都完成，说明能力已经能够迁移。

## 第一阶段：完整系统思考

这一阶段练习开发前的判断能力，不要求实现完整产品，也不受后续技术课程进度限制。

## 第一关：从模糊需求识别用户问题



### 当前情境

收到一段模糊需求：

> 我想做一个 AI 个人财务 CFO。它能记录财务数据，还能回答储蓄和负债方面的问题。



### 判断任务

- 区分用户说出的功能、真正想解决的问题和自行脑补的内容。
- 识别主要用户、典型场景和需要作出的财务决策。
- 判断哪些问题必须追问，哪些可以先作为假设。



### 最小验证

- 用一句话重新描述产品目标。
- 选取一个典型问题，列出系统回答它所需的数据。
- 说明“用户想要 AI”和“用户需要可信结论”的区别。



### 交付物

`try-ai-cfo/learning/gate-01-product-problem.md`

完成标准：

- 写清用户、场景、问题、约束和未知项。
- 能区分用户目标与功能清单。



## 第二关：澄清约束并划定完整产品 MVP



### 当前情境

完整愿景包含账户、流水、负债、目标、AI、CSV、图表和场景模拟，范围过大。

### 判断任务

- 确认本地优先、单用户、币种、金额精度和隐私要求。
- 按“必须、应该、以后”给功能分级。
- 设计一条能证明产品价值的端到端路径。



### 最小验证

检查 MVP 是否同时具备：

- 必要数据输入。
- 一个可信计算。
- 一个用户能够理解的输出。
- 可观察的验收结果。



### 交付物

`try-ai-cfo/learning/gate-02-mvp.md`

完成标准：

- 形成完整产品 MVP 和延后功能清单。
- 明确完整产品蓝图不等于本轮编码范围。



## 第三关：设计完整系统边界



### 当前情境

产品范围已经可以讨论，需要判断页面、API、校验、业务层、数据库、计算引擎和 AI 如何配合。

### 判断任务

- 为每层写出“负责什么”和“不负责什么”。
- 判断校验、数据访问、计算公式和 AI 调用分别放在哪里。
- 说明为什么采用单体全栈结构，而不是提前拆成多个服务。



### 最小验证

为以下逻辑选择归属层：

- 表单 loading。
- 请求体格式校验。
- 账户创建规则。
- SQLite 查询。
- 净资产求和。
- 自然语言意图识别。



### 交付物

`try-ai-cfo/learning/gate-03-architecture.md`

完成标准：

- 形成总体模块图和层级职责表。
- 能解释页面为什么不直接访问数据库、AI 为什么不直接计算金额。



## 第四关：画出三条核心数据流



### 当前情境

模块边界已经形成，需要确认用户操作如何穿过各层并返回结果。

### 判断任务

分别画出：

1. 账户 CRUD 数据流。
2. 确定性净资产计算数据流。
3. AI 查询净资产的数据流。

每条数据流必须标明：

- 输入从哪里产生。
- 哪一层负责校验。
- 哪一层读取或写入数据。
- 哪一层执行计算。
- 错误沿什么路径返回。



### 最小验证

给出一个故障现象，判断首先检查的层级和证据：

- 点击提交后页面没有变化。
- API 返回 400。
- 刷新后账户消失。
- AI 回复金额和页面不一致。



### 交付物

`try-ai-cfo/learning/gate-04-data-flow.md`

完成标准：

- 三条数据流完整且职责不重叠。
- 能沿数据流解释一项功能和一项故障。

## 第七关：使用假数据完成账户 CRUD



### 原始需求

> 用户需要在 Dashboard 管理自己的账户。第一版先不保存到数据库，但应支持完整操作和明确的页面状态。

Tutor 只提供需求、约束和验收标准，不提前给组件结构。

### 必须实现

- 展示账户列表。

- 输入错误提示。

### 判断任务

### 验收

## 第八关：接入 API 和 SQLite 完成真实 CRUD



### 原始需求

> 账户在刷新页面后仍然存在，非法输入不能写入数据库，所有操作都需要通过统一 API 返回结果。



### 判断任务

- 从用户操作反推 API 和数据库需求。
- 设计账户创建、读取、更新和删除接口。
- 区分 TypeScript 类型、Zod schema 和 Drizzle schema。
- 判断 Route Handler、service 和数据库各自负责什么。
- 将页面从本地数据源迁移到 API。



### 必须打通

```txt
页面加载
  → GET 账户

表单提交
  → POST 新增账户

编辑确认
  → PATCH 更新账户

删除确认
  → DELETE 删除账户
```



### 验收

- 创建、读取、修改、删除都能从页面触发。
- 非法金额和空名称被 Zod 拒绝。
- API 成功和失败响应结构一致。
- 刷新页面后数据仍然存在。
- 数据库结果与页面状态一致。
- 页面具备 loading、empty、error 和 submitting 状态。



### 交付物

`try-ai-cfo/learning/gate-08-persistent-crud.md`

## 第九关：沿数据流完成调试和证据记录



### 当前情境

功能表面可用不代表链路可靠，需要主动制造和排查问题。

### 调试任务

至少覆盖：

- 前端事件没有阻止默认行为。
- 请求体字段或类型错误。
- Zod 校验失败。
- 数据库记录不存在。
- API 请求失败。
- 页面状态与响应结果不同步。



### 证据要求

每个问题都记录：

```txt
期望结果
实际结果
复现步骤
错误信息
Network 请求和响应
数据库或运行结果
可能层级
最小修复
回归检查
```



### 验收

- 能区分 lint、类型、运行时和业务逻辑问题。
- 能根据证据判断首先检查哪一层。
- 修复后验证原问题和相邻 CRUD 操作。



### 交付物

`try-ai-cfo/learning/gate-09-debugging.md`

## 第十四关：设计受限意图和失败边界



### 原始需求

> 用户可以问“我现在的净资产是多少”，系统应使用真实账户数据回答。

第一版只支持：

```txt
net_worth
```



### 判断任务

- 设计结构化意图 schema。
- 确定未知意图和非法输出的处理方式。
- 判断缺少账户数据时是否继续计算。
- 明确哪些数据可以发送给模型。
- 明确模型不能绕过计算函数直接给金额。



### 最小验证

- 不同问法可以映射到同一意图。
- 非法 JSON 和未知意图安全失败。
- 模型密钥不会进入浏览器代码。
- 最终金额只能来自确定性函数。



### 交付物

`try-ai-cfo/learning/gate-14-ai-design.md`

- 用户重复提交时不会产生混乱状态。

## 七、后续扩展方式

完成本轮后，不需要把 `try-ai-cfo` 扩展成 `ai-finance-cfo` 的完整复制品。

后续应继续选择新的纵向切片，例如：

- 流水录入 → 月度现金流计算 → AI 解释。
- 负债录入 → 还款策略计算 → 场景比较。
- CSV 导入 → 校验与去重 → Dashboard 汇总。
- 储蓄目标 → 复利计算 → What-if 调整。

每条切片仍遵守：

```txt
知识线先学习
  ↓
推演线再独立调用
  ↓
完成一个可验证闭环
  ↓
通过五维验收
  ↓
再选择下一条切片
```

页面数量和功能数量不是推演进度。能够独立把一个需求从判断推进到可靠验收，才是这条能力输出线的核心成果。

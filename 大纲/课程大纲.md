# AI 个人财务 CFO 项目课程大纲

## 课程定位

本课程面向编程小白，目标是从零开始，逐步完成一个可运行的 **AI 个人财务 CFO 本地版**。

课程采用项目驱动方式，不按技术名词孤立讲解，而是围绕一个完整产品逐步推进：

```txt
编程基础
  ↓
前端页面
  ↓
API 与数据库
  ↓
确定性财务计算
  ↓
AI 对话
  ↓
CSV、仪表盘、测试、隐私与部署
```

本课程最重要的原则是：

> AI 负责理解语言和组织表达，财务结果必须由确定性代码计算。

## 最终项目

最终项目：**AI 个人财务 CFO 本地版**

它不是简单记账工具，而是一个可以帮助用户理解财务状态、模拟未来选择、查看计算依据的本地优先应用。

核心能力包括：

- 手动录入账户、流水、负债。
- 导入 CSV 账单。
- 查看财务仪表盘。
- 通过 AI 对话提出财务问题。
- 计算现金流、储蓄目标、债务还款策略。
- 查看每次计算的公式、输入、中间值和结果。
- 创建 What-if 场景模拟。

## MVP 与扩展功能

为了避免项目范围过大，本课程把功能分成两层。

## 一、MVP 必做功能

课程最低完成标准是做出一个闭环版本：

- 新增和查看账户。
- 新增和查看流水。
- 新增和查看负债。
- 计算月收入、月支出、月结余、储蓄率。
- 计算一个储蓄目标是否能达成。
- 通过 AI 对话解析一个财务问题。
- 使用代码完成确定性计算。
- 保存并展示一次计算历史。
- 整理 README，能本地启动项目。

## 二、扩展功能

时间充足时继续完成：

- CSV 导入账单。
- 债务雪球法和雪崩法对比。
- What-if 场景模拟。
- 图表仪表盘。
- 更完整的错误状态和空状态。
- 私有部署或桌面封装方向调研。

学完本课程后，你应该能够：

- 理解 Web 应用的基本工作方式。
- 使用 JavaScript 和 TypeScript 编写基础业务逻辑。
- 使用 React 和 Next.js 搭建前端页面与 API。
- 使用 SQLite 和 Drizzle 保存本地财务数据。
- 使用 Zod 校验用户输入、API 入参和 AI 输出。

- 接入 DeepSeek API 做意图解析和回复生成。

## 核心数据流

## 一、CRUD 数据流

```txt
前端表单输入
  ↓
前端基础校验
  ↓
POST /api/accounts
  ↓
Zod 校验请求体
  ↓
service 层处理业务规则
  ↓
Drizzle 写入 SQLite
  ↓
返回 JSON
  ↓
前端刷新列表或显示错误
```

## 二、AI 财务问答数据流

```txt
用户输入自然语言问题
  ↓
POST /api/chat
  ↓
DeepSeek 解析为结构化意图 JSON
  ↓
Zod 校验 AI 输出
  ↓
读取 SQLite 中的财务数据
  ↓
确定性计算引擎执行计算
  ↓
保存 calculation_history
  ↓
DeepSeek 把结果解释成人话
  ↓
前端展示回复和计算过程
```

## 建议学习节奏

如果每周学习 3-4 节课，大约 9-12 周完成。

推荐节奏：

- 第 1-2 周：完成编程基础、Git 和阶段一复盘。
- 第 3-4 周：完成 React、Next.js 页面骨架和前端复盘。
- 第 5-6 周：完成 API、数据库、Zod、CRUD 和数据闭环。
- 第 7-8 周：完成财务计算引擎、审计记录和测试。
- 第 9-10 周：完成 AI 对话闭环。
- 第 11 周：完成 CSV 导入和仪表盘。
- 第 12 周：项目验收、隐私安全、构建和复盘。

## 推荐练习题

- 写一个函数：输入月收入和月支出，输出储蓄率。
- 写一个函数：输入目标金额、当前金额、每月储蓄，输出需要几个月。
- 写一个函数：输入多笔债务，按利率从高到低排序。
- 写一个 API：新增一条流水。
- 写一个页面：展示最近 10 条流水。
- 写一个 Zod schema：校验新增账户请求。
- 写一个 Prompt：把“我年底前想攒 10 万”解析成 JSON。
- 写一个测试：验证储蓄目标计算是否正确。
- 写一个空状态：当没有流水时提示用户先添加数据。
- 写一个错误状态：当 API 请求失败时显示错误提示。

## 学习注意事项

- 不要一开始追求功能完整，先让 MVP 跑起来。
- 财务计算必须由代码完成，不让 AI 直接算最终金额。
- 每个复杂功能都先写成纯函数，再接入页面或 API。
- 每次新增数据写入，都要考虑校验和错误提示。
- 每次新增计算，都要考虑测试和可解释步骤。
- 每个阶段结束后都要能演示一个小闭环。
- 学会看报错，报错是开发过程的一部分。
- 不要提交 API Key、密码、`.env.local` 等敏感信息。

## 最终验收标准

项目完成时，MVP 至少支持：

- 新增和查看账户。
- 新增和查看流水。
- 新增和查看负债。
- 计算现金流和储蓄率。
- 计算储蓄目标是否达成。
- 通过 AI 对话解析一个财务问题。
- 使用确定性代码完成计算。
- 保存并展示计算历史。
- 在仪表盘展示核心财务指标。
- README 说明项目目标、启动方式、环境变量和后续计划。

扩展验收包括：

- 对比两种债务偿还策略。
- 导入一份 CSV 账单。
- 创建 What-if 场景模拟。
- 绘制现金流趋势图。
- 完成生产构建。

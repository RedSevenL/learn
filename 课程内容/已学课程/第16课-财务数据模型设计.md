# 第 16 课：财务数据模型设计

## 本课目标

项目已经能用 Drizzle 描述并操作 `accounts` 表。

现在需要把单独的账户表扩展成更完整的财务数据模型。

这一课不急着写页面，也不急着写 API。

先把核心数据想清楚：

```txt
账户
流水
负债
目标
场景
计算历史
```

你会学到：

- Account、Transaction、Liability、Goal、Scenario、CalculationHistory 分别保存什么。
- 前端类型、Zod schema、Drizzle schema 有什么区别。
- 为什么金额字段用字符串保存。
- 为什么流水要保留 `rawPayload`。
- 为什么关键数据优先软删除。
- 为什么需要 `calculation_history` 保存计算审计记录。

学完本课后，你应该能够：

- 画出主要表之间的关系。
- 说明账户和流水之间的关联。
- 说明金额为什么不直接用普通 `number`。
- 说明 `rawPayload` 和 `calculation_history` 的意义。
- 写出主要数据库 schema 初稿。

## 一、为什么要先设计数据模型

真实应用不是只保存一个账户列表。

AI 个人财务 CFO 后续要回答的问题包括：

- 我每月结余多少？
- 两年内能不能攒够 50 万？
- 哪张信用卡应该优先还？
- 如果每月多花 2000 元，会影响储蓄目标吗？
- 某次计算是根据哪些数据得出的？

这些问题背后都需要数据。

如果数据模型一开始很混乱，后面会出现几个问题：

- 账户、流水、负债关系不清楚。
- 金额字段格式不统一。
- CSV 导入后无法追溯原始内容。
- AI 回复的计算过程无法复查。
- 删除数据后历史计算对不上。

所以现在先设计核心表。

## 二、核心实体

当前先设计六类数据：

| 实体 | 表名 | 作用 |
| --- | --- | --- |
| Account | `accounts` | 保存现金、银行卡、信用卡、投资账户 |
| Transaction | `transactions` | 保存收入、支出、转账等流水 |
| Liability | `liabilities` | 保存贷款、分期、信用卡债务 |
| Goal | `goals` | 保存储蓄目标、还债目标、大额消费目标 |
| Scenario | `scenarios` | 保存 What-if 场景参数 |
| CalculationHistory | `calculation_history` | 保存每次计算的输入、公式、结果和模型痕迹 |

它们的关系可以先这样理解：

```txt
accounts
  ↓ 一个账户有多条流水
transactions

liabilities
  独立保存负债信息

goals
  独立保存目标信息

scenarios
  保存用户假设条件

calculation_history
  保存计算审计记录
```

后续模型会继续细化。

当前先完成能支撑 MVP 的初稿。

## 三、前端类型、Zod schema、Drizzle schema 的区别

项目里会出现三种看起来相似的东西。

不要把它们混成一种。

| 类型 | 文件位置示例 | 作用 |
| --- | --- | --- |
| 前端类型 | `types/finance.ts` | 帮 React 组件理解数据形状 |
| Zod schema | `schemas/account.ts` | 在运行时校验用户输入和 API 入参 |
| Drizzle schema | `lib/db/schema.ts` | 描述数据库表结构 |

例如账户名称：

前端类型关心：

```ts
name: string;
```

Zod schema 关心：

```ts
name 必须是非空字符串
```

Drizzle schema 关心：

```ts
name 对应数据库里的 TEXT NOT NULL 字段
```

可以这样理解：

```txt
前端类型：写代码时提醒
Zod schema：程序运行时校验
Drizzle schema：数据库建表和查询
```

本课只写 Drizzle schema。

Zod 会在下一课处理。

## 四、为什么金额用字符串

财务应用最怕金额算错。

普通 JavaScript 小数存在精度问题：

```js
0.1 + 0.2
```

结果不是严格的 `0.3`。

所以本项目采用原则：

```txt
数据库里：金额保存成字符串
计算时：交给 decimal.js
展示时：格式化成人类可读文本
```

例如数据库里保存：

```txt
"20000"
"-3500"
"0.042"
```

不要保存成：

```ts
20000
-3500
0.042
```

这不是因为字符串更适合计算。

而是因为字符串适合保存精确的原始值。

真正计算时再转换成 Decimal。

## 五、为什么要保留 rawPayload

CSV 导入账单时，原始数据可能长这样：

```txt
2026-06-01,星巴克,-38.00,餐饮,支付宝
```

系统解析后可能变成：

```txt
occurred_at: 1780243200000
amount: "-38.00"
category: "餐饮"
merchant: "星巴克"
source: "csv"
```

但解析可能出错。

例如：

- 商户识别错了。
- 分类识别错了。
- 金额方向识别错了。
- 银行账单格式变化了。

所以流水表需要保留原始内容：

```txt
raw_payload
```

它的作用是：

- 方便排查导入错误。
- 方便重新解析账单。
- 方便用户核对原始记录。
- 让财务数据更可追溯。

## 六、为什么需要软删除

普通删除是：

```txt
直接从数据库删除记录
```

软删除是：

```txt
不真正删除记录，只标记 deleted_at
```

例如账户表里加一个字段：

```txt
deleted_at
```

如果值为空，表示没有删除。

如果有时间戳，表示这条数据已删除。

财务应用适合优先软删除，因为：

- 历史计算需要可追溯。
- 删除账户后，旧流水不应该突然失去上下文。
- 用户误删时有恢复空间。
- 审计记录更完整。

当前先在关键表里保留 `deleted_at`。

页面查询时，默认只查：

```txt
deleted_at 为空的数据
```

## 七、为什么需要计算历史

AI 财务问答不能只给一个结论。

例如用户问：

```txt
我两年内能攒够 50 万吗？
```

系统应该保存：

- 用户输入。
- AI 解析出的意图。
- 使用了哪些账户、流水、目标数据。
- 公式是什么。
- 中间值是什么。
- 最终结果是什么。
- AI 是否参与了解释文本。

这些内容放在：

```txt
calculation_history
```

它不是普通聊天记录。

它保存的是：

> 财务计算的审计链路。

这样后续用户可以查看：

```txt
这个结论是怎么算出来的
```

这也是本项目和普通 AI 聊天工具的关键区别。

## 八、Drizzle schema 初稿

打开：

```txt
lib/db/schema.ts
```

在已有 `accounts` 基础上，整理成下面的初稿。

```ts
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const accounts = sqliteTable("accounts", {
  id: text("id").primaryKey(),
  name: text("name").notNull(),
  type: text("type").notNull(),
  currency: text("currency").notNull().default("CNY"),
  balance: text("balance").notNull(),
  createdAt: integer("created_at").notNull(),
  updatedAt: integer("updated_at").notNull(),
  deletedAt: integer("deleted_at")
});

export const transactions = sqliteTable("transactions", {
  id: text("id").primaryKey(),
  accountId: text("account_id").references(() => accounts.id),
  occurredAt: integer("occurred_at").notNull(),
  amount: text("amount").notNull(),
  direction: text("direction").notNull(),
  category: text("category"),
  merchant: text("merchant"),
  note: text("note"),
  source: text("source").notNull(),
  rawPayload: text("raw_payload"),
  createdAt: integer("created_at").notNull(),
  updatedAt: integer("updated_at").notNull(),
  deletedAt: integer("deleted_at")
});

export const liabilities = sqliteTable("liabilities", {
  id: text("id").primaryKey(),
  name: text("name").notNull(),
  principal: text("principal").notNull(),
  remainingPrincipal: text("remaining_principal").notNull(),
  annualRate: text("annual_rate").notNull(),
  minimumPayment: text("minimum_payment"),
  dueDay: integer("due_day"),
  startDate: integer("start_date"),
  endDate: integer("end_date"),
  createdAt: integer("created_at").notNull(),
  updatedAt: integer("updated_at").notNull(),
  deletedAt: integer("deleted_at")
});

export const goals = sqliteTable("goals", {
  id: text("id").primaryKey(),
  name: text("name").notNull(),
  type: text("type").notNull(),
  targetAmount: text("target_amount").notNull(),
  currentAmount: text("current_amount").notNull(),
  targetDate: integer("target_date"),
  createdAt: integer("created_at").notNull(),
  updatedAt: integer("updated_at").notNull(),
  deletedAt: integer("deleted_at")
});

export const scenarios = sqliteTable("scenarios", {
  id: text("id").primaryKey(),
  name: text("name").notNull(),
  description: text("description"),
  inputJson: text("input_json").notNull(),
  createdAt: integer("created_at").notNull(),
  updatedAt: integer("updated_at").notNull(),
  deletedAt: integer("deleted_at")
});

export const calculationHistory = sqliteTable("calculation_history", {
  id: text("id").primaryKey(),
  intentType: text("intent_type").notNull(),
  inputJson: text("input_json").notNull(),
  formulaJson: text("formula_json").notNull(),
  outputJson: text("output_json").notNull(),
  modelTraceJson: text("model_trace_json"),
  createdAt: integer("created_at").notNull()
});
```

这是一版初稿。

它先保证核心数据能放进数据库。

字段会随着后续课程继续调整。

## 九、字段命名说明

TypeScript 里使用驼峰：

```ts
targetAmount
remainingPrincipal
createdAt
```

数据库里使用下划线：

```txt
target_amount
remaining_principal
created_at
```

这样做的原因是：

- TypeScript 代码读起来更自然。
- 数据库字段符合常见 SQL 命名习惯。
- Drizzle 可以负责两者映射。

## 十、主要字段说明

### accounts

`accounts` 保存账户。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `type` | 账户类型，如 `cash`、`bank`、`credit`、`investment` |
| `balance` | 当前余额，字符串金额 |
| `deletedAt` | 软删除时间 |

### transactions

`transactions` 保存流水。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `accountId` | 关联账户 |
| `amount` | 金额，收入可为正，支出可为负 |
| `direction` | `income`、`expense`、`transfer` |
| `source` | `manual`、`csv`、`api` |
| `rawPayload` | 原始导入内容 |

### liabilities

`liabilities` 保存负债。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `principal` | 原始本金 |
| `remainingPrincipal` | 剩余本金 |
| `annualRate` | 年利率，字符串 |
| `minimumPayment` | 最低还款额 |
| `dueDay` | 每月还款日 |

### goals

`goals` 保存目标。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `type` | 目标类型，如储蓄目标、还债目标 |
| `targetAmount` | 目标金额 |
| `currentAmount` | 当前已完成金额 |
| `targetDate` | 目标日期 |

### scenarios

`scenarios` 保存场景模拟参数。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `inputJson` | 场景输入参数 JSON 字符串 |
| `description` | 场景说明 |

例如 `inputJson` 可以保存：

```json
{
  "monthlyExtraExpense": "2000",
  "months": 24
}
```

### calculation_history

`calculation_history` 保存计算历史。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `intentType` | 用户问题类型 |
| `inputJson` | 计算输入 |
| `formulaJson` | 使用的公式和步骤 |
| `outputJson` | 计算输出 |
| `modelTraceJson` | AI 解析或解释相关信息 |

## 十一、运行 Drizzle push

保存 `schema.ts` 后，运行：

```bash
npx drizzle-kit push
```

然后检查数据库：

```bash
sqlite3 data/dev.db
```

输入：

```sql
.tables
```

应该能看到类似：

```txt
accounts             goals
calculation_history  liabilities
scenarios            transactions
```

查看某张表：

```sql
.schema transactions
```

退出：

```sql
.quit
```

如果 `push` 提示表结构变化，先认真阅读提示。

学习阶段可以接受 schema 调整。

真实项目里要更谨慎，因为表结构变化可能影响已有数据。

## 十三、不要过早设计太复杂

财务系统可以设计得很复杂。

但当前不需要一次性做完：

- 分类表。
- 预算表。
- 多币种汇率表。
- 投资持仓表。
- 还款计划表。
- 标签表。
- 附件表。

现在先完成 MVP 需要的核心模型。

判断标准是：

> 这张表能否支撑账户、流水、负债、目标、场景模拟和计算追溯。

不支撑当前闭环的内容，先不要加。

第 7 课到第 11 课，我们完成了阶段二：React 与 Next.js 前端基础。

## 一、为什么需要整理

现在 `app/dashboard/page.tsx` 能运行，但代码比较集中：

```txt
类型
假数据
展示组件
表单组件
状态
提交逻辑
页面结构
```

都放在一个页面文件里，初学时方便看完整流程。

但后面接 API、数据库、Zod 和更多财务功能时，这种写法会越来越难维护。

更清楚的分工是：

```txt
页面负责状态和业务动作
组件负责展示局部 UI
类型负责描述数据结构
假数据集中放在 lib
```

整理之后，页面行为不应该改变。

用户仍然可以：

- 打开 `/dashboard`。
- 看到已有账户。
- 输入账户名称、类型和余额。
- 提交新增账户。
- 看到错误提示和空状态。

## 五、拆出 AccountCard

创建：

```txt
components/accounts/AccountCard.tsx
```

写入：

```tsx
import type { Account } from "@/types/finance";

type AccountCardProps = {
  account: Account;
};

function getAccountTypeLabel(type: Account["type"]) {
  if (type === "bank") {
    return "银行卡";
  }

  if (type === "cash") {
    return "现金";
  }

  if (type === "credit") {
    return "信用卡";
  }

  return "投资账户";
}

export function AccountCard({ account }: AccountCardProps) {
  const balanceClassName =
    account.balance < 0 ? "text-red-600" : "text-gray-900";

  return (
    <div className="rounded-lg border border-gray-200 bg-white p-4 shadow-sm">
      <div className="flex items-start justify-between gap-4">
        <div>
          <h3 className="font-semibold text-gray-900">{account.name}</h3>
          <p className="mt-1 text-sm text-gray-500">
            类型：{getAccountTypeLabel(account.type)}
          </p>
        </div>

        <p className={`text-right text-lg font-semibold ${balanceClassName}`}>
          {account.balance.toLocaleString()} 元
        </p>
      </div>
    </div>
  );
}
```

`AccountCard` 只负责展示单个账户。

它不负责：

- 保存账户列表。
- 新增账户。
- 表单校验。
- 请求 API。

## 七、拆出 AccountList

创建：

```txt

```

写入：

```tsx
import type { Account } from "@/types/finance";
import { AccountCard } from "./AccountCard";
import { EmptyAccounts } from "./EmptyAccounts";

type AccountListProps = {
  accounts: Account[];
};

export function AccountList({ accounts }: AccountListProps) {
  if (accounts.length === 0) {
    return <EmptyAccounts />;
  }

  return (
    <section className="space-y-3">
      {accounts.map((account) => (
        <AccountCard key={account.id} account={account} />
      ))}
    </section>
  );
}
```

这个组件负责：

- 接收账户数组。
- 判断是否为空。
- 有数据时渲染多个 `AccountCard`。
- 没数据时渲染 `EmptyAccounts`。

它的数据来自 props：

```tsx
accounts: Account[];
```

这说明 `AccountList` 不自己创造账户数据。

import type { Account } from "@/types/finance";
import { ErrorMessage } from "./ErrorMessage";

type AccountFormProps = {

        <label className="block">
          <span className="text-sm font-medium text-gray-700">账户类型</span>
          <select
            value={type}

        </label>

        <label className="block">
          <span className="text-sm font-medium text-gray-700">账户余额</span>
          <input
            value={balance}
            onChange={(event) => onBalanceChange(event.target.value)}

`AccountForm` 是受控表单组件。

它不自己保存状态。

它通过 props 接收：

- 当前输入值。
- 修改输入值的函数。
- 错误信息。
- 提交函数。

## 十、整理 DashboardPage

组件拆出来后，`app/dashboard/page.tsx` 会变短。

它仍然是客户端组件，因为它使用了 `useState` 和表单事件。

```tsx
"use client";

import { useState } from "react";
import { AccountForm } from "@/components/accounts/AccountForm";
import { AccountList } from "@/components/accounts/AccountList";
import { initialAccounts } from "@/lib/mock-data";
import type { Account } from "@/types/finance";

export default function DashboardPage() {
  const [accounts, setAccounts] = useState<Account[]>(initialAccounts);
  const [name, setName] = useState("");
  const [type, setType] = useState<Account["type"]>("bank");
  const [balance, setBalance] = useState("");
  const [error, setError] = useState("");

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();

    const trimmedName = name.trim();
    const numericBalance = Number(balance);

    if (trimmedName.length === 0) {
      setError("请输入账户名称。");
      return;
    }

    if (!Number.isFinite(numericBalance)) {
      setError("请输入合法的账户余额。");
      return;
    }

    const newAccount: Account = {
      id: `account_${Date.now()}`,
      name: trimmedName,
      type,
      balance: numericBalance
    };

    setAccounts([...accounts, newAccount]);
    setName("");
    setType("bank");
    setBalance("");
    setError("");
  }

  return (
    <main className="min-h-screen bg-gray-50 px-6 py-8">
      <div className="mx-auto max-w-4xl">
        <header className="mb-8">
          <p className="text-sm font-medium text-gray-500">Dashboard</p>
          <h1 className="mt-2 text-3xl font-bold text-gray-900">财务仪表盘</h1>
          <p className="mt-2 max-w-2xl text-sm text-gray-600">
            先管理现金、银行卡、信用卡和投资账户。
            后续会在这里扩展收入、支出、结余、储蓄率和近期流水。
          </p>
        </header>

        <AccountForm
          name={name}
          type={type}
          balance={balance}
          error={error}
          onNameChange={setName}
          onTypeChange={setType}
          onBalanceChange={setBalance}
          onSubmit={handleSubmit}
        />

        <section className="mt-8">
          <div className="mb-4">
            <h2 className="text-lg font-semibold text-gray-900">账户列表</h2>
            <p className="mt-1 text-sm text-gray-500">
              当前共有 {accounts.length} 个账户。
            </p>
          </div>

          <AccountList accounts={accounts} />
        </section>
      </div>
    </main>
  );
}
```

页面仍然负责：

- 保存 `accounts` 状态。
- 保存表单输入状态。
- 校验输入。
- 新增账户。
- 把数据和函数传给子组件。

组件负责：

- 显示表单。
- 显示错误。
- 显示账户列表。
- 显示单个账户。

## 十一、理解 props 数据流

整理后的数据流是：

```txt
DashboardPage
  ├── 状态：accounts、name、type、balance、error
  ├── 函数：handleSubmit、setName、setType、setBalance
  │
  ├── AccountForm
  │     ├── 接收 name、type、balance、error
  │     └── 调用 onNameChange、onTypeChange、onBalanceChange、onSubmit
  │
  └── AccountList
        └── 接收 accounts
              └── AccountCard
                    └── 接收 account
```

更简单地说：

```txt
页面准备数据
  ↓ props
子组件展示数据
  ↓ 回调函数
页面更新状态
```

子组件不能直接修改父组件状态。

如果子组件需要触发修改，就让父组件把函数传给它。

例如：

```tsx
<AccountForm onNameChange={setName} />
```

输入框变化时，`AccountForm` 调用：

```tsx
onNameChange(event.target.value)
```

最终还是 `DashboardPage` 里的 `setName` 更新状态。

## 十二、复盘 empty、error、loading

当前账户管理已经用到了两个基础状态：

| 状态 | 当前例子 | 作用 |
| --- | --- | --- |
| empty | `EmptyAccounts` | 账户为空时提示下一步 |
| error | `ErrorMessage` | 输入不合法时展示原因 |

loading 暂时还没真正用上。

后面接 API 时会加入：

```txt
点击提交
  ↓
isSubmitting = true
  ↓
POST /api/accounts
  ↓
请求完成
  ↓
isSubmitting = false
```

所以本课可以先理解：

- empty 解决“没有数据时显示什么”。
- error 解决“出错时怎么告诉用户”。
- loading 解决“等待时怎么避免重复操作”。

## 十三、和第 13 课的衔接

第 13 课会学习 HTTP 和 API。

账户 API 可以直接承接本课整理出的假数据：

```txt
lib/mock-data.ts
  ↓
initialAccounts
  ↓
GET /api/accounts
```

也就是说，第 13 课不需要再新增一份名字不同的账户假数据。

可以这样写：

```tsx
import { initialAccounts } from "@/lib/mock-data";

export async function GET() {
  return Response.json({
    ok: true,
    data: {
      accounts: initialAccounts
    }
  });
}
```

本课结束后，数据来源仍然是前端假数据。

第 13 课只是先让 API 能返回这份假数据。

页面暂时不需要改成 `fetch`。

后面课程会再把数据来源替换成：

```txt
SQLite
  ↓
service
  ↓
API
  ↓
前端页面
```

这一课不是重做页面，而是整理第 7 到第 11 课已经完成的账户管理功能。

你需要记住三句话：

1. 页面负责状态和业务动作，组件负责展示局部 UI。
2. 类型和假数据要集中管理，避免散落在页面里。
3. React 的基础数据流是“页面 → props → 子组件”，子组件通过回调函数触发父组件更新。

本课结束后，`/dashboard` 仍然是账户管理为主的财务仪表盘。

下一课会进入 HTTP 与 API。我们会让 `GET /api/accounts` 返回本课整理出的账户假数据，为后续 SQLite 和数据库读写做准备。

# 第 23 课：复利与储蓄目标计算

## 本课目标

第 22 课把账户和流水汇总成了真实现金流指标：

```txt
月收入
月支出
月结余
储蓄率
安全现金月数
```

其中，月结余回答的是：

> 按照目前的收入和支出，这个月能剩下多少钱？

这一课继续向未来推演，回答另一个常见问题：

> 我现在有 10 万元，每月能存 1.2 万元，按照年化 3% 计算，两年内能攒够 50 万元吗？

要回答这个问题，不能只计算：

```txt
当前金额 + 每月储蓄 × 月数
```

因为本金和每月投入的资金还可能产生收益。

本课会完成：

```txt
当前金额
目标金额
每月储蓄
年化收益率
期限
  ↓
确定性储蓄目标计算
  ↓
预计期末金额
是否达成目标
缺口或超额
达成目标所需月储蓄额
```

学完后，你应该能够：

- 区分本金、月存款、年化收益率和期限。
- 把年化收益率转换成月收益率。
- 理解一次性本金和每月储蓄的复利公式。
- 正确处理年化收益率为 `0` 的情况。
- 使用 `Decimal` 完成复利计算。
- 判断储蓄目标是否达成。
- 返回目标缺口或超额金额。
- 反推达成目标所需的月储蓄额。
- 说明计算结果依赖哪些假设。
- 为正常值、零收益率和异常值编写测试。

## 二、从现金流连接到储蓄目标

第 22 课得到的：

```txt
surplus
```

可以作为本课：

```txt
monthlySaving
```

的参考值。

例如，本月现金流是：


| 项目  | 金额       |
| --- | -------- |
| 月收入 | 20,000 元 |
| 月支出 | 8,000 元  |
| 月结余 | 12,000 元 |


那么可以先假设：

```txt
每月储蓄 = 12000
```

但二者不能永远直接画等号。

原因包括：

- 某个月可能有一次性奖金。
- 某个月可能有临时大额支出。
- 用户可能只准备把部分结余用于目标。
- 历史单月结余不一定能代表未来 24 个月。

因此，本课的计算函数仍然把 `monthlySaving` 作为明确输入。

页面以后可以用月结余提供默认值，但最终应由用户确认。

## 三、先认识五个输入

储蓄目标计算需要五个核心输入。

### 1. 目标金额 targetAmount

最终希望拥有的金额。

例如：

```txt
500000.00
```

表示目标是 50 万元。

### 2. 当前金额 currentAmount

现在已经为这个目标准备好的金额。

例如：

```txt
100000.00
```

这部分资金会从第一个月开始产生收益。

### 3. 每月储蓄 monthlySaving

以后每个月投入的金额。

例如：

```txt
12000.00
```

本课统一假设：

> 每月储蓄在每个月末投入。

如果改成月初投入，结果会略高，公式也会不同。

### 4. 年化收益率 annualRate

本课使用百分数形式。

例如：

```txt
"3"
```

表示：

```txt
3%
```

不要传：

```txt
"0.03"
```

否则它会被理解为 `0.03%`。

### 5. 期限 months

本课统一使用月数，避免“2 年”到底包含多少个月的歧义。

例如：

```txt
2 年 = 24 个月
```



## 四、先计算不考虑收益的情况

假设：

```txt
当前金额 = 100000
每月储蓄 = 12000
期限 = 24 个月
年化收益率 = 0%
```

计算：

```txt
期末金额
= 当前金额 + 每月储蓄 × 月数
= 100000 + 12000 × 24
= 388000
```

目标是 50 万元，因此缺口是：

```txt
500000 - 388000 = 112000
```

如果完全没有收益，要在 24 个月达到 50 万元，所需月储蓄额是：

```txt
(500000 - 100000) ÷ 24
= 16666.666...
```

金额只能保留到分，而且不能因为普通四舍五入导致最终少几分钱。

因此所需月储蓄额要向上取到分：

```txt
16666.67
```



## 五、复利和单利有什么区别

单利只让最初的本金产生收益。

复利则会让：

```txt
本金产生收益
收益继续产生收益
```

例如，月收益率为 `1%`：

```txt
第 1 个月：10000 × 1.01 = 10100
第 2 个月：10100 × 1.01 = 10201
```

第二个月的收益不是只根据最初的 `10000` 计算，而是根据：

```txt
本金 + 第一个月收益
```

继续计算。

这就是复利。

## 六、把年化收益率转换成月收益率

本课采用适合入门项目的名义年利率口径：

```txt
月收益率 = 年化收益率 ÷ 100 ÷ 12
```

例如：

```txt
年化收益率 = 3%
```

先把百分数转换为小数：

```txt
3 ÷ 100 = 0.03
```

再转换为月收益率：

```txt
0.03 ÷ 12 = 0.0025
```

也就是：

```txt
0.25%
```

注意，本课没有使用：

```txt
(1 + 年化收益率)^(1/12) - 1
```

后者适用于把“有效年收益率”换算成等效月收益率。

两种口径都可能出现在真实产品中，不能混用。

本课明确约定：

> `annualRate` 是按月计息的名义年化百分比，月收益率等于年化收益率除以 12。



## 七、一次性本金的未来价值

当前金额会完整经历所有月份的复利。

公式：

```txt
当前金额的期末价值
= 当前金额 × (1 + 月收益率)^月数
```

使用符号表示：

```txt
P = 当前金额
r = 月收益率
n = 月数

本金期末价值 = P × (1 + r)^n
```

如果：

```txt
P = 100000
r = 0.0025
n = 24
```

那么：

```txt
本金期末价值
= 100000 × (1 + 0.0025)^24
```



## 八、每月储蓄的未来价值

每月投入的资金经历复利的时间不同。

采用月末投入时：

```txt
第 1 个月投入的钱，会继续增长 23 个月
第 2 个月投入的钱，会继续增长 22 个月
...
第 24 个月投入的钱，期末刚刚投入
```

把它们逐笔相加，可以整理为年金终值公式：

```txt
每月储蓄的期末价值
= 每月储蓄 × ((1 + 月收益率)^月数 - 1) ÷ 月收益率
```

使用符号表示：

```txt
PMT = 每月储蓄

每月储蓄期末价值
= PMT × ((1 + r)^n - 1) ÷ r
```

这里的 `PMT` 不是额外的技术类型，只是财务公式里常用的“每期投入金额”缩写。

## 九、完整的储蓄目标公式

把本金和每月储蓄合并：

```txt
预计期末金额
= 当前金额 × (1 + 月收益率)^月数
+ 每月储蓄 × ((1 + 月收益率)^月数 - 1) ÷ 月收益率
```

写成符号：

```txt
FV
= P × (1 + r)^n
+ PMT × ((1 + r)^n - 1) ÷ r
```

其中：


| 符号    | 含义     |
| ----- | ------ |
| `FV`  | 预计期末金额 |
| `P`   | 当前金额   |
| `PMT` | 每月储蓄   |
| `r`   | 月收益率   |
| `n`   | 月数     |




## 十、年化收益率为 0 时必须单独处理

年金终值公式中包含：

```txt
÷ 月收益率
```

如果年化收益率为 `0`，月收益率也是 `0`。

这时直接套公式会变成：

```txt
0 ÷ 0
```

程序不能计算。

但业务结果并不复杂：

```txt
预计期末金额
= 当前金额 + 每月储蓄 × 月数
```

因此实现时要明确分支：

```txt
月收益率 = 0
  → 使用简单累加

月收益率 > 0
  → 使用复利公式
```

这不是“特殊补丁”，而是公式本身的定义域要求。

## 十一、反推所需月储蓄额

完整公式是：

```txt
目标金额
= 当前金额期末价值
+ 所需月储蓄额 × 年金因子
```

把所需月储蓄额移到等号左边：

```txt
所需月储蓄额
= (目标金额 - 当前金额期末价值) ÷ 年金因子
```

其中：

```txt
年金因子
= ((1 + 月收益率)^月数 - 1) ÷ 月收益率
```

如果当前金额仅靠复利就已经能达到目标：

```txt
目标金额 - 当前金额期末价值 <= 0
```

则所需月储蓄额返回：

```txt
"0.00"
```

不能返回负数。

## 十二、为什么所需月储蓄额要向上取整

假设精确结果是：

```txt
16666.666...
```

如果保留两位小数时向下取成：

```txt
16666.66
```

持续存 24 个月后仍会略低于目标。

因此本课规定：

> 预计金额、缺口和超额按普通四舍五入显示；所需月储蓄额向上取到分。

使用 `Decimal` 时对应：

```ts
Decimal.ROUND_CEIL
```

因为所需月储蓄额一定是非负数，所以 `ROUND_CEIL` 会向更大的金额取整。

## 十六、实现储蓄目标计算函数

在 `savings-goal.ts` 中继续写入：

```ts
export function calculateSavingsGoal(
  input: SavingsGoalInput
): SavingsGoalResult {
  const targetAmount = createMoney(input.targetAmount);
  const currentAmount = createMoney(input.currentAmount);
  const monthlySaving = createMoney(input.monthlySaving);
  const annualRate = new Decimal(input.annualRate);

  if (!annualRate.isFinite()) {
    throw new Error("年化收益率必须是有限数字");
  }

  if (targetAmount.lessThanOrEqualTo(0)) {
    throw new Error("目标金额必须大于 0");
  }

  assertNonNegative(currentAmount, "当前金额");
  assertNonNegative(monthlySaving, "每月储蓄");
  assertNonNegative(annualRate, "年化收益率");
  assertMonths(input.months);

  const monthlyRate = annualRate
    .dividedBy(100)
    .dividedBy(12);

  let growthFactor: Decimal;
  let annuityFactor: Decimal;

  if (monthlyRate.isZero()) {
    growthFactor = new Decimal(1);
    annuityFactor = new Decimal(input.months);
  } else {
    growthFactor = monthlyRate
      .plus(1)
      .pow(input.months);

    annuityFactor = growthFactor
      .minus(1)
      .dividedBy(monthlyRate);
  }

  const currentAmountFutureValue =
    currentAmount.times(growthFactor);

  const monthlySavingFutureValue =
    monthlySaving.times(annuityFactor);

  const projectedAmount =
    currentAmountFutureValue.plus(
      monthlySavingFutureValue
    );

  const reached =
    projectedAmount.greaterThanOrEqualTo(targetAmount);

  const gap = reached
    ? new Decimal(0)
    : targetAmount.minus(projectedAmount);

  const excess = reached
    ? projectedAmount.minus(targetAmount)
    : new Decimal(0);

  const amountNeededAfterCurrentGrowth =
    targetAmount.minus(currentAmountFutureValue);

  const requiredMonthlySaving =
    amountNeededAfterCurrentGrowth.lessThanOrEqualTo(0)
      ? new Decimal(0)
      : amountNeededAfterCurrentGrowth
          .dividedBy(annuityFactor);

  return {
    targetAmount: toMoneyString(targetAmount),
    currentAmount: toMoneyString(currentAmount),
    monthlySaving: toMoneyString(monthlySaving),
    annualRate: annualRate.toString(),
    months: input.months,
    projectedAmount: toMoneyString(projectedAmount),
    reached,
    gap: toMoneyString(gap),
    excess: toMoneyString(excess),
    requiredMonthlySaving:
      requiredMonthlySaving.toFixed(
        2,
        Decimal.ROUND_CEIL
      )
  };
}
```



## 十七、理解代码中的两个因子

代码先计算：

```ts
growthFactor
```

它表示：

```txt
(1 + 月收益率)^月数
```

用于计算当前金额的期末价值。

代码还计算：

```ts
annuityFactor
```

它表示：

```txt
((1 + 月收益率)^月数 - 1) ÷ 月收益率
```

用于计算一系列月末存款的期末价值。

把两个因子单独命名，比把整条公式挤在一行中更容易：

- 阅读。
- 测试。
- 检查。
- 在第 26 课记录计算过程。



## 十八、为什么判断目标时不能先格式化

代码使用：

```ts
projectedAmount.greaterThanOrEqualTo(targetAmount)
```

而不是先执行：

```ts
toMoneyString(projectedAmount)
```

再比较。

原因是格式化会把金额四舍五入到两位小数。

假设内部结果是：

```txt
499999.996
```

格式化后可能显示：

```txt
500000.00
```

但精确计算结果仍然略低于目标。

本课统一：

> 业务判断使用未格式化的 `Decimal`，展示输出最后才保留两位小数。



## 十九、计算“两年内能攒够 50 万吗”

使用输入：

```ts
const result = calculateSavingsGoal({
  targetAmount: "500000",
  currentAmount: "100000",
  monthlySaving: "12000",
  annualRate: "3",
  months: 24
});
```

计算口径：

```txt
目标金额：500000 元
当前金额：100000 元
每月储蓄：12000 元
名义年化收益率：3%
期限：24 个月
每月末投入
```

结果应接近：

```ts
{
  targetAmount: "500000.00",
  currentAmount: "100000.00",
  monthlySaving: "12000.00",
  annualRate: "3",
  months: 24,
  projectedAmount: "402609.52",
  reached: false,
  gap: "97390.48",
  excess: "0.00",
  requiredMonthlySaving: "15942.49"
}
```

结论是：

```txt
按照这些假设，24 个月后预计有 402609.52 元。
距离 50 万元还差 97390.48 元。
若其他条件不变，每月至少需要储蓄 15942.49 元。
```

注意：

```txt
缺口 ÷ 24
```

并不等于准确的“每月还要多存多少”。

因为新增的每月储蓄也会在不同月份经历不同时间的复利。

正确做法是使用年金因子反推。

## 二十四、测试当前金额已经足够

## 二十九、真实世界中的收益率不是承诺

本课公式假设：

- 收益率固定。
- 每月按相同收益率计息。
- 每月末按时投入。
- 没有税费。
- 没有管理费和交易费。
- 没有中途取出。
- 没有通货膨胀调整。

真实投资收益可能：

- 上涨。
- 下跌。
- 每月不同。
- 出现本金亏损。

因此产品不能把结果写成：

```txt
你两年后一定会有 402609.52 元。
```

更准确的表达是：

```txt
按照年化 3%、每月末投入 12000 元的假设，
24 个月后的预计金额为 402609.52 元。
```

这是确定性计算和现实不确定性之间的重要区别：

> 代码可以准确执行给定公式，但输入假设不代表未来一定发生。

## 三十一、常见错误



### 1. 把 `3%` 直接当成 `3`

月收益率应该是：

```txt
3 ÷ 100 ÷ 12
```

不能写成：

```txt
3 ÷ 12
```

否则收益率会放大 100 倍。

### 2. 使用普通 `Math.pow` 和 number

不要把 `Decimal` 转成 `number` 再计算：

```ts
Math.pow(1 + Number(monthlyRate), months)
```

应该继续使用：

```ts
monthlyRate.plus(1).pow(months)
```



### 3. 忘记处理零收益率

零收益率会让年金公式出现除以 `0`。

必须单独走简单累加分支。

### 4. 月初投入和月末投入混用

本课统一月末投入。

如果页面文案说“月初投入”，代码却使用月末年金公式，展示假设与计算结果就不一致。

### 5. 用格式化后的金额做业务判断

是否达标应该比较原始 `Decimal`，不能先四舍五入再比较。

### 6. 所需月储蓄使用普通四舍五入

普通四舍五入可能让建议金额略低于真正需要的金额。

本课使用 `ROUND_CEIL` 向上取到分。

### 7. 把预测结果写成保证结果

复利计算是基于输入假设的情景预测，不是收益承诺。

## 三十五、复习问题



### 1. 为什么当前金额和每月储蓄不能直接相加？

当前金额会经历完整期限的复利，而每月储蓄进入账户的时间不同，经历复利的月份也不同。

### 2. 本课如何把年化收益率转换为月收益率？

本课把 `annualRate` 视为名义年化百分比，使用：

```txt
月收益率 = 年化收益率 ÷ 100 ÷ 12
```



### 3. 为什么收益率为 0 时要单独处理？

年金终值公式需要除以月收益率。月收益率为 `0` 时会发生除以 `0`，此时应该改用“当前金额加每月储蓄乘月数”的简单累加。

### 4. 什么是月末投入假设？

它表示每笔月储蓄在当月结束时才进入计算。最后一个月的储蓄在期末刚刚投入，不再获得一个完整月的收益。

### 5. 为什么所需月储蓄额要向上取到分？

如果向下取整，最终累计金额可能仍比目标少几分钱。向上取到分可以保证建议金额不低于计算所需金额。

### 6. 为什么判断 `reached` 时不能先保留两位小数？

两位小数格式化可能把略低于目标的金额显示成目标金额。业务判断应该使用未格式化的高精度结果。

### 7. `gap` 和 `excess` 为什么不同时为正？

未达标时只有缺口；达标时只有超额。另一项返回 `"0.00"`，让结果含义稳定明确。

### 8. 第 22 课的月结余和本课的每月储蓄是什么关系？

月结余可以作为未来每月储蓄的参考或默认值，但单月结余可能包含偶发收入和支出，最终输入仍应由用户确认。

### 9. 计算结果为什么不是收益承诺？

代码能准确执行公式，但固定收益率、按时投入、无税费等都只是假设，真实未来可能不同。

### 10. 为什么本课暂时不保存 goals 和 calculation_history？

本课先保证纯计算规则正确。目标数据的读取与保存属于外部层，计算历史和步骤会在第 26 课专门处理。

## 三十六、本课小结

这一课把当前财务状态延伸成了未来目标预测：

```txt
当前金额
  ↓ 完整期限复利
当前金额期末价值

每月储蓄
  ↓ 月末年金终值
每月储蓄期末价值
```

两部分合并后得到：

```txt
预计期末金额
  ↓ 与目标金额比较
是否达成

```

```txt

当前金额
年化收益率
期限
  ↓
达成目标至少需要的月储蓄额
```

项目现在已经能够用确定性代码回答：

> 按照明确的本金、月存款、收益率和期限假设，我能否达成储蓄目标？

```txt

最低还款
利息成本

```

储蓄目标关注“钱如何积累”，第 24 课则会关注“债务如何减少”。

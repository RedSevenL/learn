# 第 11 课：搭建项目页面骨架

## 本课目标

上一课我们学习了 Next.js App Router，并创建了几个可以访问的页面：

```txt
/
/dashboard
/import
/scenarios
```

这说明项目已经从单页练习，变成了多页面应用。

但现在还有几个问题：

- 页面之间的结构不够统一。
- 顶部导航可能还比较简单。
- 每个页面的标题、说明和内容区域没有统一规范。
- 假数据可能散落在不同页面里。
- 对话页 `/chat` 还没有加入页面骨架。

这一课要解决的问题是：

> 如何把项目整理成一个结构清晰、页面完整、方便继续开发的前端骨架。

你会学到：

- 如何规划项目页面结构。
- 如何设计顶部导航。
- 如何写统一页面容器。
- 如何给每个页面安排标题、说明和占位内容。
- 如何集中管理前端假数据。
- 如何搭建对话页、仪表盘、场景模拟页和 CSV 导入页。

学完本课后，你应该能够：

- 说清楚项目有哪些核心页面。
- 在 `layout.tsx` 中放置公共导航。
- 让所有页面有统一布局。
- 用假数据展示页面骨架。
- 知道为什么先搭骨架，再补功能。

## 一、为什么要先搭页面骨架

真实项目不是一上来就写所有功能。

更稳妥的顺序是：

```txt
确定页面结构
  ↓
搭建页面骨架
  ↓
放入假数据和占位内容
  ↓
逐步实现交互
  ↓
接入 API 和数据库
```

页面骨架的作用是：

- 让项目整体结构先跑通。
- 让每个功能有明确位置。
- 方便后续逐页填充真实功能。
- 避免所有代码都堆在首页。
- 方便检查用户是否能理解页面入口。

对于 AI 个人财务 CFO，本阶段不是要一次性完成所有功能。

本课只要求：

> 页面结构完整，用户能看到每个核心模块未来会做什么。

## 二、本项目的核心页面

上一课已经创建了首页，以及 `/dashboard`、`/import`、`/scenarios` 三个功能页。

其中 `/dashboard` 已经承接了第 10 课迁移过来的账户管理功能。

本课会补上对话页 `/chat`，并把项目整理成四个核心功能页面：

| 页面 | 路径 | 作用 |
| --- | --- | --- |
| 对话页 | `/chat` | 用户用自然语言提出财务问题 |
| 仪表盘 | `/dashboard` | 先保留账户管理，后续逐步扩展财务摘要 |
| 场景模拟 | `/scenarios` | 模拟未来选择对财务状态的影响 |
| CSV 导入 | `/import` | 导入账单流水 |

首页 `/` 暂时作为入口页。

所以目录结构可以调整为：

```txt
app/
  layout.tsx
  page.tsx
  chat/
    page.tsx
  dashboard/
    page.tsx
  import/
    page.tsx
  scenarios/
    page.tsx
```

后面项目变复杂后，还会继续增加：

```txt
app/
  accounts/
  transactions/
  liabilities/
  settings/
```

## 三、页面骨架的统一结构

每个页面都应该有相似结构。

推荐结构：

```txt
页面外层
  ↓
页面容器
  ↓
页面标题区
  ↓
主要内容区
  ↓
占位内容或假数据
```

对应 JSX 可以是：

```tsx
<main className="min-h-screen bg-gray-50 px-6 py-8">
  <div className="mx-auto max-w-5xl">
    <header className="mb-8">
      <p className="text-sm font-medium text-gray-500">模块名称</p>
      <h1 className="mt-2 text-3xl font-bold text-gray-900">页面标题</h1>
      <p className="mt-2 text-sm text-gray-600">页面说明文字。</p>
    </header>

    <section>
      页面内容
    </section>
  </div>
</main>
```

这样做的好处是：

- 每个页面都有清楚标题。
- 页面宽度一致。
- 留白一致。
- 后续加功能时不会乱。

`/dashboard` 和其他页面有一点不同。

其他新页面大多是占位内容，可以直接按这个骨架从零写。

`app/dashboard/page.tsx` 已经有第 10 课留下来的账户管理代码，不要重写整个文件。

它的调整方式是：

```txt
保留原来的账户管理逻辑
  ↓
把外层 main、容器、header 调整成统一骨架
  ↓
让新增账户表单和账户列表继续放在内容区
```

## 四、顶部导航应该放在哪里

顶部导航属于所有页面共享内容。

所以适合放在：

```txt
app/layout.tsx
```

而不是每个页面重复写一遍。

导航至少包含：

- 首页。
- 对话。
- 仪表盘。
- 场景模拟。
- CSV 导入。

先写一个导航数组：

```tsx
const navItems = [
  { href: "/", label: "首页" },
  { href: "/chat", label: "对话" },
  { href: "/dashboard", label: "仪表盘" },
  { href: "/scenarios", label: "场景模拟" },
  { href: "/import", label: "CSV 导入" }
];
```

再用 `.map()` 渲染：

```tsx
{navItems.map((item) => (
  <Link
    key={item.href}
    href={item.href}
    className="text-sm font-medium text-gray-600 hover:text-gray-900"
  >
    {item.label}
  </Link>
))}
```

这和前面账户列表的 `.map()` 思路一样：

```txt
定义数组
  ↓
map 渲染多个元素
```

本课后面还会看到很多类似写法：

```tsx
featureCards.map((feature) => (...))
scenarioCards.map((scenario) => (...))
importSteps.map((step) => (...))
```

它们都可以按同一个句式读：

> 对数组里的每一项，生成一块对应的页面内容。

```tsx
import type { Metadata } from "next";
import Link from "next/link";
import "./globals.css";

export const metadata: Metadata = {

  children

}>) {
  return (
    <html lang="zh-CN">
      <body>
        <header className="border-b border-gray-200 bg-white">

                  key={item.href}
                  href={item.href}
                  className="text-sm font-medium text-gray-600 hover:text-gray-900"
```

访问 `/chat` 时，`ChatPage` 会出现在 `{children}` 的位置。

## 十三、为什么不急着拆组件

你可能会发现，页面里有一些重复结构：

- 页面标题区。
- 卡片样式。
- 页面容器。

这些以后都可以拆成组件。

例如：

```txt
components/
  PageHeader.tsx
  StatCard.tsx
  AppShell.tsx
```

但本课暂时不急着拆。

原因是：

> 初学阶段先看清楚页面结构，再抽组件会更稳。

如果一开始就拆太多文件，容易不知道数据从哪里来、页面从哪里开始。

下一课复盘时，会开始整理组件目录和前端数据流。

## 十四、运行和检查

启动项目：

```bash
npm run dev
```

依次访问：

```txt
http://localhost:3000/
http://localhost:3000/chat
http://localhost:3000/dashboard
http://localhost:3000/scenarios
http://localhost:3000/import
```

检查：

- 顶部导航是否每个页面都有。
- 点击导航是否能切换页面。
- 每个页面是否有标题和说明。
- 每个页面是否有占位内容。
- 控制台是否有明显报错。

如果路径 404，优先检查：

- 文件夹是否创建在 `app/` 下。
- 文件是否命名为 `page.tsx`。
- 路径拼写是否一致。

如果导入 `@/lib/mock-data` 报错，检查：

- 是否创建了 `lib/mock-data.ts`。
- 项目是否支持 `@/` 路径别名。

如果 `@/` 路径别名不能用，可以先改成相对路径，例如：

```tsx
import { featureCards } from "../lib/mock-data";
```

不过 Next.js 默认项目通常已经配置好了 `@/`。

## 十五、常见错误

### 1. 页面没有统一导航

如果只有首页有导航，其他页面没有导航，用户进入后就不方便切换。

推荐把导航放在 `app/layout.tsx`。

### 2. 假数据散落在各个页面

短期可以跑，但后面会难维护。

建议先把假数据放到：

```txt
lib/mock-data.ts
```

等接入 API 后，再逐步替换。

### 3. 首页承载太多功能

首页应该是入口，不应该把对话、仪表盘、导入、模拟全部堆在一个页面里。

多页面应用要让每个页面职责清楚。

### 4. 页面只有标题，没有内容区域

页面可以还没有真实功能，但不能空着。

至少要有：

- 标题。
- 说明。
- 占位卡片。
- 后续功能方向。

### 5. 过早拆太多组件

拆组件不是越早越好。

当你发现某块结构在多个页面重复，并且职责清晰时，再拆更合适。

## 十九、本课小结

这一课我们把项目从“有几个能访问的页面”，推进成了“有完整页面骨架的应用”。

你需要记住三句话：

1. 页面骨架先解决结构问题，不急着实现所有功能。
2. 顶部导航、页面容器和标题区要保持一致。
3. 页面骨架整理不能丢掉前面已经完成的账户管理功能。

本课最重要的实践成果是：

> 搭建对话页、场景模拟页和 CSV 导入页，整理首页和顶部导航，同时保留 `/dashboard` 里的账户管理功能。

下一课会做阶段二复盘。我们会整理组件目录、抽取前端临时类型，复盘 props、状态、空状态、错误状态，以及前端假数据未来如何替换成 API 数据。

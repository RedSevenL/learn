# 第 1 课：项目全貌与学习路线

## 本课目标

这节课不要求你马上写代码。作为编程小白，第一节课最重要的是先看清楚：

- 我们到底要做一个什么项目。
- 这个项目为什么需要前端、后端、数据库、AI、计算引擎。
- 为什么不能让 AI 直接给财务结论。
- MVP 和扩展功能有什么区别。
- 接下来 35 节课会如何一步一步完成它。

学完本课后，你应该能用自己的话解释：

- 什么是 **AI 个人财务 CFO**。
- 用户问一个财务问题时，系统内部大概发生了什么。
- Next.js、React、TypeScript、SQLite、Drizzle、DeepSeek 分别负责什么。
- 为什么本项目最核心的不是“AI 聊天”，而是“可信计算”。
- 为什么课程要先完成 MVP，再逐步扩展 CSV、图表和场景模拟。

## 一、我们要做的项目是什么

项目名称可以理解为：

> AI 个人财务 CFO

CFO 是公司里的首席财务官，负责看钱、管钱、做预算、评估风险和辅助决策。

我们要做的是个人版 CFO。它不是简单记账软件，而是一个能帮你回答财务问题的工具。

普通记账软件通常回答：

- 我这个月花了多少钱？
- 我在哪些分类上花钱最多？
- 我还有多少钱？

而 AI 个人财务 CFO 要进一步回答：

- 我两年内能攒够 50 万吗？
- 如果我每月多花 3000 元，会影响年底目标吗？
- 我应该先还哪笔债？
- 如果收入下降 20%，我能撑几个月？
- 这笔大额消费会不会让我现金流变危险？

也就是说，它的重点不是“记录过去”，而是：

- 理解现在的财务状态。
- 预测未来的财务变化。
- 对比不同选择的后果。
- 给出可以解释的建议。

## 二、MVP 和扩展功能

这个项目最终会包含不少功能。

但对于编程小白来说，不能一开始就追求完整版本。

课程会先完成一个 MVP。

MVP 可以理解为：

> 最小可用版本。

它不是最终形态，但必须能跑通核心闭环。

本课程的 MVP 包括：

- 新增和查看账户。
- 新增和查看流水。
- 新增和查看负债。
- 计算月收入、月支出、月结余、储蓄率。
- 计算一个储蓄目标是否能达成。
- 通过 AI 对话解析一个财务问题。
- 使用代码完成确定性计算。
- 保存并展示一次计算历史。

等 MVP 跑通后，再继续扩展：

- CSV 导入账单。
- 债务策略对比。
- What-if 场景模拟。
- 图表仪表盘。
- 私有部署或桌面封装方向。

这样安排的原因很简单：

> 先让核心链路可用，再让产品变完整。

## 三、一个典型使用场景

假设用户问：

> 我两年内能攒够 50 万吗？

系统不能只靠 AI 随便回答“可以”或“不可以”。它应该经历下面的过程：

```txt
用户提问
  ↓
AI 理解问题含义
  ↓
提取结构化参数
  ↓
读取用户财务数据
  ↓
确定性计算引擎计算
  ↓
保存计算过程
  ↓
AI 把结果解释成人话
  ↓
展示给用户
```

更具体一点：

```txt
用户："我两年内能攒够 50 万吗？"

AI 解析：
{
  "type": "savings_goal",
  "targetAmount": "500000",
  "deadlineMonths": 24
}

系统读取数据：
- 当前存款：120000 元
- 每月收入：30000 元
- 每月支出：15000 元
- 每月可储蓄：15000 元

计算引擎计算：
120000 + 15000 × 24 = 480000

系统结论：
按当前储蓄速度，两年后预计 480000 元，距离 500000 元还差 20000 元。
```

注意这里最重要的一点：

> AI 负责理解“用户想问什么”，但最终金额必须由代码计算。

## 四、为什么不能让 AI 直接做财务计算

很多初学者会想：既然 AI 很聪明，为什么不直接把问题丢给 AI，让它算完回答？

原因很简单：财务结果必须准确、稳定、可检查。

LLM 适合做：

- 理解自然语言。
- 提取用户意图。
- 总结和解释。
- 把复杂结果说得更容易懂。

LLM 不适合直接做：

- 精确金额计算。
- 长期现金流预测。
- 多笔债务利息计算。
- 可审计的财务结论。

比如用户问：

> 我每月存 12345 元，年化 3.2%，连续 37 个月后有多少钱？

AI 可能能给出一个看起来合理的答案，但这个答案不一定稳定。今天问一次、明天问一次，结果可能不一样。甚至它可能在公式细节上犯错。

财务应用不能接受这种情况。

所以本项目采用一条非常重要的原则：

> LLM 只做语言翻译，核心逻辑交给确定性代码。

确定性代码的意思是：

- 同样的输入，每次得到同样的输出。
- 计算过程可以写测试。
- 每一步公式可以展示给用户。
- 出错时能定位是哪一段逻辑的问题。

## 五、项目由哪些部分组成

这个项目可以拆成五大部分。

### 1. 前端界面

前端就是用户能看见、能点击、能输入的部分。

包括：

- 对话页面。
- 财务仪表盘。
- 账户列表。
- 流水列表。
- 负债列表。
- CSV 导入页面。
- 场景模拟页面。

本项目使用：

- React：用来写界面组件。
- TailwindCSS：用来控制样式。
- Next.js：用来组织页面和项目结构。

### 2. 后端 API

后端 API 是前端和数据、计算、AI 之间的桥梁。

比如：

- 前端提交一条新流水，API 负责保存到数据库。
- 前端发送一句财务问题，API 负责调用 AI 和计算引擎。
- 前端请求仪表盘数据，API 负责汇总后返回。

本项目使用 Next.js 自带的 Route Handler 来写 API。

你可以先简单理解为：

> API 是前端向系统“办事”的入口。

### 3. 数据库

数据库用来保存用户的财务数据。

包括：

- 账户。
- 收支流水。
- 负债。
- 储蓄目标。
- 模拟场景。
- 计算历史。

本项目使用 SQLite，因为它适合个人本地应用：

- 不需要单独部署数据库服务器。
- 一个文件就能保存数据。
- 适合本地优先的隐私策略。

我们还会使用 Drizzle ORM。

你可以先简单理解为：

> Drizzle 是 TypeScript 代码和数据库之间的翻译层。

### 4. 财务计算引擎

这是项目最核心的部分。

计算引擎负责：

- 计算月度现金流。
- 计算储蓄目标是否能达成。
- 计算复利。
- 计算债务还清时间。
- 对比不同场景的结果。

计算引擎会写成一组 TypeScript 函数。

例如：

```ts
function calculateMonthlySurplus(income: number, expense: number) {
  return income - expense;
}
```

后面我们不会直接用普通 `number` 做真实金额计算，而会学习 `decimal.js`，避免小数精度问题。

### 5. AI 意图解析

AI 负责把用户的自然语言问题转换成系统能理解的结构。

例如：

```txt
用户说：
"我年底前想攒 10 万，每个月要存多少？"

AI 转换成：
{
  "type": "savings_goal",
  "targetAmount": "100000",
  "deadline": "年底"
}
```

然后系统再把这个结构交给计算引擎。

这个过程叫：

> 意图解析

本项目计划使用 DeepSeek API 完成这部分。

## 六、技术栈用大白话解释

下面这些技术现在看起来可能很多，但不用害怕。每个工具只负责一部分事情。

| 技术 | 大白话解释 | 在项目中的作用 |
| --- | --- | --- |
| HTML | 网页的骨架 | 页面基础结构 |
| CSS | 网页的样式 | 控制颜色、间距、布局 |
| JavaScript | 让网页动起来的语言 | 写交互逻辑 |
| TypeScript | 更安全的 JavaScript | 降低代码写错的概率 |
| React | 写界面的工具 | 拆分页面组件 |
| Next.js | React 全栈框架 | 同时写页面和 API |
| TailwindCSS | 快速写样式的工具 | 美化界面 |
| SQLite | 本地数据库 | 保存财务数据 |
| Drizzle | 数据库操作工具 | 用 TS 操作 SQLite |
| Zod | 数据校验工具 | 检查输入是否合法 |
| decimal.js | 精确数字计算工具 | 避免金额计算误差 |
| DeepSeek API | AI 模型接口 | 理解用户问题 |
| Vitest | 测试工具 | 验证计算结果正确 |

你不需要在第一天全部掌握。课程会按照使用顺序逐步学习。

## 七、系统工作流程

可以把整个系统想象成一个流水线。

```txt
用户输入问题
  ↓
前端页面接收问题
  ↓
调用 /api/chat
  ↓
DeepSeek 解析用户意图
  ↓
Zod 校验 AI 输出
  ↓
从 SQLite 读取财务数据
  ↓
计算引擎执行确定性计算
  ↓
保存 calculation_history
  ↓
DeepSeek 组织自然语言回复
  ↓
前端展示答案和计算过程
```

这里有两个关键点：

第一，AI 输出不能直接相信，必须校验。

第二，计算结果必须保存，方便用户查看依据。

## 九、本课重点概念

### 1. 前端

用户能看到和操作的部分。

例如按钮、输入框、聊天窗口、图表。

### 2. 后端

用户看不到，但负责处理业务逻辑的部分。

例如保存数据、调用 AI、执行计算。

### 3. 数据库

保存长期数据的地方。

例如账户余额、消费记录、负债记录。

### 4. API

前端和后端沟通的入口。

例如前端调用 `POST /api/chat`，把用户问题发给后端。

### 5. LLM

大语言模型。

在本项目中，它主要负责理解自然语言和组织回复。

### 6. 确定性计算

由代码完成的稳定计算。

同样的输入必须得到同样的输出。

### 7. 审计

记录一次计算是如何得出结果的。

包括输入、公式、过程和输出。

# 第 8 课账户表单编程思路

## 一、先把需求说清楚

这次页面要做的事是：

> 用户填写账户信息，点击新增账户后，页面把新账户加入账户列表。

把这句话拆开，可以得到几个小需求：

1. 页面一开始有一组账户数据。
2. 页面能展示账户列表。
3. 用户能输入账户名称。
4. 用户能选择账户类型。
5. 用户能输入账户余额。
6. 点击提交时要校验输入。
7. 校验通过后创建一个新账户对象。
8. 把新账户加入账户列表。
9. 提交成功后清空表单。
10. 输入错误时显示错误提示。

写代码时不要一上来就写完整表单。

更稳的方式是：

```txt
先定义数据长什么样
  ↓
先把假数据展示出来
  ↓
再让列表可以变化
  ↓
再加表单输入
  ↓
最后处理提交和校验
```

## 二、第一层：定义数据结构

先问：

> 一个账户对象应该长什么样？

当前账户需要这些字段：

```txt
id       唯一标识
name     账户名称
type     账户类型
balance  账户余额
```

所以先写类型：

```tsx
type Account = {
  id: string;
  name: string;
  type: "cash" | "bank" | "credit" | "investment";
  balance: number;
};
```

这一步的作用是：

> 先把数据规则定下来，后面所有组件和函数都围绕这个规则写。

然后准备初始数据：

```tsx
const initialAccounts: Account[] = [
  {
    id: "account_001",
    name: "工资卡",
    type: "bank",
    balance: 20000
  }
];
```

这一步是为了先有数据可展示。

## 三、第二层：先做展示组件

有了数据之后，先不要急着写表单。

先解决：

> 如何把账户显示在页面上？

展示可以拆成两层。

第一层：单个账户怎么显示。

```tsx
function AccountCard({ account }: AccountCardProps) {
  return (
    <div>
      <h2>{account.name}</h2>
      <p>类型：{account.type}</p>
      <p>余额：{account.balance} 元</p>
    </div>
  );
}
```

第二层：账户数组怎么显示。

```tsx
function AccountList({ accounts }: AccountListProps) {
  return (
    <section>
      {accounts.map((account) => (
        <AccountCard key={account.id} account={account} />
      ))}
    </section>
  );
}
```

拆成两个组件的原因是：

```txt
AccountCard 负责一个账户
AccountList 负责一组账户
```

这样代码层次更清楚。

## 四、第三层：把会变化的数据放进状态

账户列表会变化，因为用户会新增账户。

所以不能只写：

```tsx
const accounts = initialAccounts;
```

要写成状态：

```tsx
const [accounts, setAccounts] = useState<Account[]>(initialAccounts);
```

这一步的思路是：

```txt
页面上会变化的数据
  ↓
放进 useState
```

账户列表以后通过 `setAccounts` 更新。

例如新增一个账户：

```tsx
setAccounts([...accounts, newAccount]);
```

意思是：

> 用旧账户列表和新账户组成一个新数组，再交给 React 保存。

## 五、第四层：先用按钮验证新增流程

在写正式表单前，可以先写一个测试按钮。

这样可以先验证：

```txt
创建新账户
  ↓
更新 accounts
  ↓
页面重新渲染
```

代码：

```tsx
function addTestAccount() {
  const newAccount: Account = {
    id: `account_${Date.now()}`,
    name: "测试账户",
    type: "cash",
    balance: 500
  };

  setAccounts([...accounts, newAccount]);
}
```

页面中：

```tsx
<button onClick={addTestAccount}>新增测试账户</button>
<AccountList accounts={accounts} />
```

如果点击按钮后列表能多一项，说明状态更新逻辑是通的。

这一步很重要。

它让你不用同时面对表单、校验、状态更新三个问题。

## 六、第五层：为表单准备状态

正式表单里，用户输入的内容也会变化。

所以输入内容也要放进状态：

```tsx
const [name, setName] = useState("");
const [type, setType] = useState<Account["type"]>("bank");
const [balance, setBalance] = useState("");
const [error, setError] = useState("");
```

这些状态不是账户对象本身。

它们更像是：

> 用户正在填写的表单草稿。

对应关系：

| 状态 | 作用 |
| --- | --- |
| `name` | 当前输入的账户名称 |
| `type` | 当前选择的账户类型 |
| `balance` | 当前输入的账户余额 |
| `error` | 当前错误提示 |

等用户提交时，再用这些草稿组装成真正的 `newAccount`。

## 七、第六层：把表单输入和状态绑起来

输入框要做到两件事：

1. 显示当前状态。
2. 用户输入时更新状态。

例如账户名称：

```tsx
<input
  value={name}
  onChange={(event) => setName(event.target.value)}
  placeholder="例如：工资卡"
/>
```

可以读作：

```txt
输入框里显示 name
用户输入时，把输入框的新内容保存回 name
```

这里：

- `value` 是输入框当前显示的内容。
- `onChange` 是输入框内容变化时触发的事件。
- `event` 是这次输入变化产生的事件对象。
- `event.target` 是触发事件的输入框。
- `event.target.value` 是输入框当前的新内容。

下拉框也是同样思路：

```tsx
<select
  value={type}
  onChange={(event) => setType(event.target.value as Account["type"])}
>
  <option value="bank">银行卡</option>
  <option value="cash">现金</option>
  <option value="credit">信用卡</option>
  <option value="investment">投资账户</option>
</select>
```

余额输入框也是同样思路：

```tsx
<input
  value={balance}
  onChange={(event) => setBalance(event.target.value)}
  placeholder="例如：20000"
/>
```

## 八、第七层：处理提交

表单提交时要做的事比较多。

可以先写成步骤：

```txt
阻止浏览器默认刷新
  ↓
整理输入
  ↓
校验输入
  ↓
创建 newAccount
  ↓
更新 accounts
  ↓
清空表单
```

对应代码：

```tsx
function handleSubmit(event: React.SubmitEvent<HTMLFormElement>) {
  event.preventDefault();

  const trimmedName = name.trim();
  const numericBalance = Number(balance);

  if (trimmedName.length === 0) {
    setError("请输入账户名称。");
    return;
  }

  if (!Number.isFinite(numericBalance)) {
    setError("请输入合法的账户余额。");
    return;
  }

  const newAccount: Account = {
    id: `account_${Date.now()}`,
    name: trimmedName,
    type,
    balance: numericBalance
  };

  setAccounts([...accounts, newAccount]);
  setName("");
  setType("bank");
  setBalance("");
  setError("");
}
```

这里最重要的是顺序。

先校验，再创建账户。

如果校验失败，就：

```tsx
setError("请输入账户名称。");
return;
```

`return` 会提前结束函数，后面的新增逻辑不会执行。

## 九、第八层：把提交函数接到表单上

有了 `handleSubmit` 后，把它交给表单：

```tsx
<form onSubmit={handleSubmit}>
  ...
  <button type="submit">新增账户</button>
</form>
```

这里的意思是：

```txt
用户点击提交按钮
  ↓
触发表单 submit
  ↓
执行 handleSubmit
```

按钮要写：

```tsx
<button type="submit">新增账户</button>
```

这样它才会触发表单提交。

## 十、第九层：显示错误和空状态

错误提示来自 `error` 状态。

```tsx
{error && <p className="text-red-600">{error}</p>}
```

可以读作：

```txt
如果 error 有内容，就显示 error
如果 error 是空字符串，就不显示
```

空状态放在 `AccountList` 里：

```tsx
if (accounts.length === 0) {
  return (
    <p>
      暂无账户，请先新增一个账户。
    </p>
  );
}
```

这一步是为了避免列表为空时页面一片空白。

## 十一、整体代码层次

当前 `page.tsx` 可以分成五层：

```txt
第 1 层：客户端声明和导入
  "use client"
  import { useState } from "react"

第 2 层：数据结构
  type Account
  initialAccounts

第 3 层：展示组件
  AccountCard
  AccountList

第 4 层：页面状态和提交逻辑
  accounts / name / type / balance / error
  handleSubmit

第 5 层：页面结构
  标题
  form
  AccountList
```

写代码时也建议按这个顺序填：

```txt
先写类型
再写假数据
再写展示
再写状态
再写事件
再写表单
最后补校验和提示
```

## 十二、从需求到代码的通用方法

以后遇到类似页面，可以按这个问题列表拆：

1. 页面要管理什么数据？
2. 这些数据哪些是固定的，哪些会变化？
3. 每一条数据长什么样？先定义类型。
4. 哪些组件只负责展示？
5. 哪些数据需要放进 `useState`？
6. 用户会触发哪些事件？
7. 每个事件要按什么步骤处理？
8. 哪些输入需要校验？
9. 成功后更新哪个状态？
10. 失败时显示什么错误？

这就是从需求走到代码的基本路线。

## 十三、本课代码的核心模式

这一课真正练的是一个常见模式：

```txt
表单状态
  ↓
用户输入
  ↓
提交事件
  ↓
校验
  ↓
生成新对象
  ↓
更新列表状态
  ↓
页面重新渲染
```

后面做流水录入、负债录入、储蓄目标设置，也会反复使用这个模式。

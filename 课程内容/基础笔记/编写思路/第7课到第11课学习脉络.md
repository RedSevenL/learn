# 第 7 课到第 11 课学习脉络

## 一、整体主线

这一段学习不是在学几个互不相关的语法点，而是在完成一次前端项目升级：

```txt
TS / DOM 练习
  ↓
找大数游戏
  ↓
React 组件
  ↓
React 状态与表单
  ↓
TailwindCSS 基础 UI
  ↓
Next.js 多页面路由
  ↓
项目页面骨架
```

可以压缩成一句话：

> 先学会让数据变成页面，再学会让用户操作改变数据，最后把单页面整理成多页面项目。

前两个练习和 React 项目不是割裂的。

它们的关系是：

| 阶段 | 主要练什么 | 后面怎么继承 |
| --- | --- | --- |
| TS 代码练习 | 类型、DOM、事件、请求、渲染表格 | React 里继续使用类型、事件、列表渲染、后续 API 请求 |
| 找大数游戏 | 从需求拆代码、状态、纯逻辑、render、事件 | React 里变成 `useState`、事件函数、自动渲染 |
| React 项目 | 组件、props、状态、表单、页面路由 | 形成可继续开发的前端项目骨架 |

这一阶段可以先抓住三层：

```txt
JavaScript：变量、对象、数组、函数、判断、循环
  ↓
TypeScript：给变量、参数、返回值、对象结构加类型
  ↓
React：用组件、props、状态和 JSX 组织页面
```

## 二、代码结构：从一个文件到项目骨架

### 1. TS / DOM 练习的结构

TS 代码练习里，代码大致按这个结构组织：

```txt
接口地址和 DOM 元素
  ↓
数据类型 interface
  ↓
数据类 class
  ↓
页面渲染方法
  ↓
请求函数
  ↓
事件绑定
```

核心是：

```txt
拿到数据
  ↓
创建 DOM
  ↓
插入页面
```

比如：

- `DogType` 描述接口数据。
- `getJSON<T>()` 请求数据。
- `WebDisplay.addData()` 把数据渲染到表格。
- `addEventListener` 绑定点击事件。

这一阶段更接近浏览器底层：自己找 DOM，自己改 DOM。

### 2. 找大数游戏的结构

找大数游戏开始有了更完整的“程序结构”：

```txt
HTML：页面上有什么
CSS：页面怎么摆
TypeScript 类型：核心概念有哪些
state：程序要记住什么
纯逻辑函数：生成数字、找最大值
render：把状态显示到页面
事件函数：用户操作后修改状态
```

这里第一次形成了清晰的状态模式：

```txt
state
  ↓
render()
  ↓
页面
```

以及事件模式：

```txt
用户操作
  ↓
修改 state
  ↓
调用 render()
```

这就是后面 React 状态的前身。

### 3. React 账户表单的结构

第 8 课账户表单代码可以分成四层：

```txt
环境声明与导入
  "use client"
  useState

类型和初始数据
  type Account
  initialAccounts

展示组件
  AccountCard
  AccountList

页面组件
  useState 状态
  handleSubmit 提交逻辑
  JSX 页面结构
```

对应关系是：

| 普通 DOM / 游戏写法 | React 写法 |
| --- | --- |
| HTML 结构 | JSX |
| CSS 样式 | TailwindCSS 的 `className` |
| `state` 对象 | 多个 `useState` |
| `render()` | React 自动重新渲染 |
| `addEventListener` | `onChange`、`onSubmit`、`onClick` |
| 手动 `appendChild` | 更新状态后 `.map()` 渲染列表 |

React 没有取消前面的思路，而是把它换成组件化写法。

### 4. 第 10 到第 11 课的项目结构

后面项目从一个页面变成多个页面：

```txt
app/
  layout.tsx
  page.tsx
  chat/
    page.tsx
  dashboard/
    page.tsx
  import/
    page.tsx
  scenarios/
    page.tsx
lib/
  mock-data.ts
```

每个文件的职责：

| 文件 | 作用 |
| --- | --- |
| `app/layout.tsx` | 所有页面共享的外壳和顶部导航 |
| `app/page.tsx` | 首页入口，展示功能模块入口 |
| `app/chat/page.tsx` | AI 财务对话页骨架 |
| `app/dashboard/page.tsx` | 财务仪表盘页骨架 |
| `app/scenarios/page.tsx` | 场景模拟页骨架 |
| `app/import/page.tsx` | CSV 导入页骨架 |
| `lib/mock-data.ts` | 当前阶段集中保存假数据 |

可以这样记：

```txt
app/ 负责页面和路由
lib/ 负责可复用数据和逻辑
```

## 三、思考及编写顺序

### 1. 通用思考顺序

从找大数游戏到 React 项目，都可以按这个顺序想：

```txt
页面上有什么
  ↓
程序要管理什么数据
  ↓
哪些数据会变化
  ↓
数据长什么样
  ↓
哪些内容只是展示
  ↓
用户会做哪些操作
  ↓
每个操作如何改变数据
  ↓
数据变化后页面如何更新
```

这个顺序比直接想语法更重要。

语法只是实现工具。

### 2. 普通 TS / DOM 的编写顺序

普通浏览器练习里，推荐顺序是：

```txt
写 HTML
  ↓
写 CSS
  ↓
定义类型
  ↓
定义状态
  ↓
写纯逻辑函数
  ↓
获取 DOM 元素
  ↓
写 render()
  ↓
绑定事件
```

比如找大数游戏：

1. 先写按钮和 A-D 区域。
2. 再写样式。
3. 定义 `Zone` 和 `GameState`。
4. 定义 `state`。
5. 写 `generateNumbers()`。
6. 写 `getMaxZone()`。
7. 写 `render()`。
8. 最后绑定点击事件。

### 3. React 账户表单的编写顺序

React 里顺序类似，但不再手动查 DOM：

```txt
定义数据类型
  ↓
准备初始数据
  ↓
先写展示组件
  ↓
把会变化的数据放进 useState
  ↓
写表单状态
  ↓
绑定输入框 value / onChange
  ↓
写 submit 事件
  ↓
校验、创建新对象、更新列表
```

账户表单具体就是：

1. 定义 `Account`。
2. 准备 `initialAccounts`。
3. 写 `AccountCard`。
4. 写 `AccountList`。
5. 在 `Home` 里写 `accounts` 状态。
6. 写 `name`、`type`、`balance`、`error` 表单状态。
7. 输入框绑定 `value` 和 `onChange`。
8. `handleSubmit` 里校验并创建 `newAccount`。
9. 用 `setAccounts([...accounts, newAccount])` 更新列表。

### 4. 多页面项目的编写顺序

第 10 到第 11 课开始整理项目骨架。

顺序是：

```txt
先保留已有账户管理功能
  ↓
把账户管理迁移到 /dashboard
  ↓
把 / 改成首页入口
  ↓
创建 /import 和 /scenarios
  ↓
补上 /chat
  ↓
把公共导航放进 layout.tsx
  ↓
把假数据集中到 lib/mock-data.ts
```

这里的重点不再是一个表单怎么写，而是：

> 每个功能应该放在哪个页面，公共内容放在哪里，假数据放在哪里。

## 四、功能流程：数据如何流动

### 1. TS 代码练习的流程

Dog API 练习的流程是：

```txt
点击按钮
  ↓
执行 getData()
  ↓
fetch 请求接口
  ↓
拿到 DogType 数据
  ↓
WebDisplay.addData(data)
  ↓
创建表格行
  ↓
appendChild 到页面
```

删除流程是：

```txt
点击 X
  ↓
事件委托拿到 ev.target
  ↓
判断是不是 HTMLAnchorElement
  ↓
找到父级 tr
  ↓
remove()
```

这一阶段的关键词是：

```txt
DOM 查询
事件监听
手动渲染
手动删除
```

### 2. 找大数游戏的流程

游戏流程是：

```txt
点击开始
  ↓
初始化 state
  ↓
生成 A-D 随机数
  ↓
render()
```

选择答案流程：

```txt
点击 A-D
  ↓
判断是否正在游戏
  ↓
getMaxZone 找最大值
  ↓
更新题数和得分
  ↓
生成下一题
  ↓
render()
```

这个练习强化了一个核心：

> 事件函数 = 修改状态 + 重新渲染。

### 3. React 账户表单的流程

账户表单流程是：

```txt
用户输入账户名称 / 类型 / 余额
  ↓
onChange 更新表单状态
  ↓
点击新增账户
  ↓
触发表单 onSubmit
  ↓
handleSubmit 执行
  ↓
校验 name 和 balance
  ↓
创建 newAccount
  ↓
setAccounts([...accounts, newAccount])
  ↓
React 自动重新渲染账户列表
```

这里和找大数游戏很像。

区别是：

```txt
找大数游戏：自己调用 render()
React：调用 setState 后自动 render
```

### 4. 多页面项目的流程

第 10 到第 11 课的流程是页面级别的：

```txt
用户访问 /
  ↓
看到首页功能卡片
  ↓
点击 Link
  ↓
跳转到 /chat、/dashboard、/scenarios、/import
```

页面数据流程是：

```txt
lib/mock-data.ts
  ↓
页面 import 数据
  ↓
.map() 渲染卡片、列表、步骤
```

例如：

```tsx
featureCards.map((feature) => (
  <Link key={feature.href} href={feature.href}>
    {feature.title}
  </Link>
))
```

可以读作：

> 对每一个功能卡片数据，生成一个可点击的页面入口。

## 五、几个容易混在一起的概念

### 1. JS 基础语法和 TS 类型标注

JavaScript 先负责“程序怎么运行”：

| 内容 | 例子 | 作用 |
| --- | --- | --- |
| 变量 | `const name = "工资卡"` | 保存一个值 |
| 模板字符串 | `` `账户 ${name}` `` | 拼接文字和变量 |
| 布尔判断 | `surplus > 0`、`type === "income"` | 得到 `true` 或 `false` |
| 数组 | `const expenses = [3000, 1200]` | 保存一组数据 |
| 对象 | `{ name: "工资卡", balance: 20000 }` | 保存一条结构化数据 |
| `if` | `if (surplus > 0) { ... }` | 按条件执行 |
| `for...of` | `for (const expense of expenses)` | 遍历数组 |
| 函数 | `function calculate(...) { return ... }` | 封装一段逻辑 |

TypeScript 在这些基础上加类型：

```ts
const category: string = "餐饮";

function calculateSurplus(income: number, expense: number): number {
  return income - expense;
}
```

对象结构可以用 `type` 或 `interface` 描述：

```ts
type MonthlySummary = {
  income: number;
  expense: number;
  surplus: number;
  isDeficit: boolean;
  message: string;
};
```

注意：

- `type` 写法用 `=`。
- `interface` 写法不用 `=`。

例如：

```ts
interface Account {
  id: string;
  name: string;
  type: AccountType;
  balance: number;
  note?: string;
}
```

`note?: string` 里的 `?` 表示可选字段，使用前要考虑它可能不存在。

联合类型可以限制可选值：

```ts
type AccountType = "cash" | "bank" | "credit" | "investment";
```

对象数组写法：

```ts
const accounts: Account[] = [
  {
    id: "account_001",
    name: "工资卡",
    type: "bank",
    balance: 20000
  }
];
```

这一组知识对应后面的 React 账户数据：

```txt
JS 对象
  ↓
TS 对象类型
  ↓
React 组件 props
  ↓
页面展示
```

### 2. HTML / JSX / DOM

| 概念 | 怎么理解 |
| --- | --- |
| HTML | 浏览器页面结构 |
| DOM | 浏览器把 HTML 变成的对象树 |
| JSX | React 里描述页面结构的写法 |

普通练习里，你经常写：

```ts
document.querySelector()
element.textContent = "..."
```

React 里通常写：

```tsx
<h1>{title}</h1>
```

React 会帮你处理 DOM 更新。

### 3. 对象、数组和 .map()

前面 JS 里学过：

```ts
const account = {
  name: "工资卡",
  type: "cash",
  balance: 20000
};
```

读取对象属性常用点号：

```ts
account.name
```

数组里可以放对象：

```ts
const accounts = [
  { name: "工资卡", balance: 20000 },
  { name: "现金", balance: 1000 }
];
```

React 里经常用 `.map()` 把对象数组变成 JSX 数组：

```tsx
accounts.map((account) => (
  <AccountCard key={account.id} account={account} />
))
```

可以读作：

> 对 `accounts` 里的每一个账户对象，生成一个 `AccountCard`。

这里的 `key` 是 React 用来识别列表项的标记。

### 4. state 和 useState

找大数游戏里：

```ts
const state = {
  round: 0,
  score: 0
};
```

React 里：

```tsx
const [score, setScore] = useState(0);
```

它们都表示程序需要记住的变化数据。

区别是：

- 普通对象改完后，需要自己调用 `render()`。
- React 状态改完后，React 会重新渲染页面。

`useState` 返回两个东西：

```tsx
const [name, setName] = useState("");
```

可以读作：

```txt
name 是当前状态值
setName 是修改 name 的函数
```

调用 `setName(...)` 后，React 会重新计算页面显示。

### 5. addEventListener 和 JSX 事件

普通 DOM：

```ts
button.addEventListener("click", handleClick);
```

React：

```tsx
<button onClick={handleClick}>点击</button>
```

本质都是：

```txt
用户触发事件
  ↓
执行函数
```

### 6. 受控组件和 onChange

React 表单输入框里常见：

```tsx
<input
  value={name}
  onChange={(event) => setName(event.target.value)}
/>
```

这叫受控组件。

意思是：

```txt
输入框显示什么
  ↓
由 React 状态 name 决定

用户输入
  ↓
触发 onChange
  ↓
调用 setName
  ↓
React 重新渲染
  ↓
输入框显示新的 name
```

所以不是 `onChange` 自己直接决定最终显示结果。

最终显示结果由 `value={name}` 和 `useState` 共同决定。

### 7. render 和 React 自动渲染

找大数游戏：

```ts
function render() {
  statusPanel.textContent = `得分：${state.score}`;
}
```

React：

```tsx
<p>得分：{score}</p>
```

然后通过：

```tsx
setScore(score + 1);
```

让 React 自动更新页面。

### 8. props

`props` 可以先理解为：

> 父组件传给子组件的参数对象。

比如：

```tsx
<AccountCard account={account} />
```

这里左边的 `account` 是 prop 名。

右边的 `{account}` 是当前作用域里的变量。

子组件接收：

```tsx
function AccountCard({ account }: AccountCardProps) {
  return <h3>{account.name}</h3>;
}
```

props 的特点是：

- 从父组件传到子组件。
- 子组件只负责读取和展示。
- 不要在子组件里直接修改 props。

### 9. 展开语法

账户表单里有：

```tsx
setAccounts([...accounts, newAccount]);
```

这里的：

```tsx
...accounts
```

表示把旧数组里的每一项展开出来。

整体意思是：

```txt
旧账户列表
  +
新账户
  ↓
组成一个新数组
  ↓
交给 setAccounts
```

React 里通常不要直接修改旧数组，而是创建新数组后更新状态。

### 10. 数据写在页面里和放到 lib 里

早期页面里可以直接写：

```tsx
const links = [...]
```

项目变大后，改成：

```tsx
import { featureCards } from "@/lib/mock-data";
```

这样页面更专注于显示，数据集中管理。

### 11. 工具链：Node.js、npm、npx

项目构建工具可以简单记：

| 工具 | 作用 |
| --- | --- |
| Node.js | 让 JavaScript 工具能在电脑终端里运行 |
| npm | 安装依赖、执行 `package.json` 里的脚本 |
| npx | 临时运行工具，例如 `create-next-app` |

比如：

```bash
npm run dev
```

实际是：

```txt
npm 读取 package.json
  ↓
找到 dev 脚本
  ↓
执行 next dev
  ↓
启动 Next.js 开发服务器
```

## 六、现在应该怎么回顾

建议按这三个问题回顾：

### 1. 代码结构

每看到一个文件，先问：

```txt
这个文件负责页面、组件、数据，还是配置？
```

比如：

- `app/page.tsx`：首页页面。
- `app/layout.tsx`：公共外壳。
- `lib/mock-data.ts`：假数据。
- `app/dashboard/page.tsx`：仪表盘页面。

### 2. 编写顺序

每做一个功能，先问：

```txt
数据是什么？
哪些数据会变化？
页面怎么展示？
用户怎么操作？
操作后数据怎么变？
```

不要先从语法开始想。

### 3. 功能流程

每看一段代码，顺着流程读：

```txt
用户做了什么
  ↓
触发哪个函数
  ↓
函数改了什么数据
  ↓
页面哪里发生变化
```

这是从 TS 练习、找大数游戏到 React 项目都通用的读法。

## 七、当前最重要的结论

这一段学习的核心不是某个单独语法，而是三条线：

### 1. 结构线

```txt
一个 HTML/TS 文件
  ↓
一个 React 页面
  ↓
多个 React 组件
  ↓
多个 Next.js 页面
  ↓
项目骨架
```

### 2. 状态线

```txt
普通变量
  ↓
state 对象
  ↓
useState
  ↓
状态驱动页面
```

### 3. 流程线

```txt
用户事件
  ↓
函数处理
  ↓
数据变化
  ↓
页面更新
```

只要抓住这三条线，前面那些语法就不会全混在一起。

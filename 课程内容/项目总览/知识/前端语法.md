### 0.2 2-8 原则：先学带 ⭐ 的核心

学习同样遵循 2-8 原则：项目里大约 20% 的语法承担了 80% 的代码量，这 20% 需要更深刻的理解。

**第一轮学习只读 ⭐ 章节**，做到能读懂、能照着写；第二轮再补其余内容，把基础打牢。文档最后的「复习路线」也按这个原则设计。

### 0.5 先分清 TSX 里的五种花括号

这是阅读 TSX 最容易混淆的地方，先记住它，后面所有代码都基于此：

```tsx
// ① 函数体
function Example() {
  // ...
}

// ② JavaScript 对象
const account = {
  name: "工资卡",
  balance: "20000",
};

// ③ JSX 中插入 JavaScript 表达式
<p>{account.name}</p>

// ④ JSX 属性接收 JavaScript 值
<button disabled={isSubmitting}>提交</button>

// ⑤ JSX 属性接收对象
<Line tick={{ fontSize: 12, fill: "#6b7280" }} />
```

口诀：进入 JSX 后，普通文本直接写；需要计算、读取变量或传非字符串值时，用一层 `{}` 回到 JavaScript。

### 0.6 一份典型客户端文件长什么样

项目里的客户端页面大多可以拆成固定的九个层次（以 dashboard 页为代表）：

```tsx
"use client"; // ① 声明这是客户端组件

import { useState } from "react"; // ② 导入运行时要使用的值
import type { Account } from "@/types/finance"; // ③ 只导入类型

type AccountPanelProps = { // ④ 定义组件接收的数据
  initialAccounts: Account[];
};

function formatCount(count: number): string { // ⑤ 普通辅助函数
  return `${count} 个账户`;
}

export function AccountPanel({ initialAccounts }: AccountPanelProps) { // ⑥ 组件
  const [accounts, setAccounts] = useState<Account[]>(initialAccounts); // ⑦ 状态

  function handleClear() { // ⑧ 事件处理函数
    setAccounts([]);
  }

  return ( // ⑨ JSX 画面
    <section>
      <p>{formatCount(accounts.length)}</p>
      <button type="button" onClick={handleClear}>清空</button>
    </section>
  );
}
```

可以先记住一句话：普通变量保存数据，函数处理数据，组件返回 JSX，State 让画面随数据变化，Effect 负责渲染之外的外部同步。

# 第一部分：JavaScript 基础



## 1. 模块：`import` 与 `export` ⭐

几乎每个文件的第一段代码都是导入，这是必须滚瓜烂熟的内容。

### 1.1 四种导入

```tsx
// ① 默认导入：对方使用 export default
import Link from "next/link";

// ② 具名导入：名字必须与对方导出的名字一致
import { useEffect, useRef, useState } from "react";

// ③ 只导入类型：编译后不会产生运行时代码
import type { Account } from "@/types/finance";

// ④ 同时导入值和类型
import {
  useState,
  type FormEvent,
} from "react";
```

**为什么** `import type` **重要**：它只存在于 TypeScript 检查阶段，打包成浏览器 JavaScript 后会被移除。类型不是运行时的东西，不写 `type` 也能跑，但写上是正确习惯，也提示读者「这只是个类型」。

### 1.2 路径别名 `@/`

项目中的 `@/` 指向 `ai-finance-cfo/` 根目录，来自 `tsconfig.json`：

```json
{
  "paths": {
    "@/*": ["./*"]
  }
}
```

因此：

```tsx
import { AccountForm } from "@/components/accounts/AccountForm";
```

表示从项目根目录下的 `components/accounts/AccountForm` 导入，可以避免多层 `../../`。

### 1.3 三种导出

```tsx
// ① 具名导出常量（metadata 约定写法）
export const metadata = {
  title: "AI Finance CFO",
};

// ② 具名导出函数（可复用组件）
export function MetricCard() {
  return <article>指标</article>;
}

// ③ 默认导出：一个模块最多一个，Next.js 页面常用
export default function HomePage() {
  return <main>首页</main>;
}
```

项目约定：**页面文件用默认导出**（Next.js 靠它识别页面），**可复用组件用命名导出**。

项目位置：

- `app/layout.tsx`（默认导出 + metadata 具名导出）
- `app/page.tsx`（默认导出）
- `components/dashboard/MetricCard.tsx`（命名导出）

## 2. 变量、值、数组和对象



### 2.1 `const` 与 `let`

```ts
// 不会重新赋值时使用 const（项目里绝大多数情况）
```

## 3. 函数的四种形式 ⭐

项目代码里函数有四种写法，各有用处。

### 3.1 普通函数（声明式）

```ts
function getDefaultMonth() {
  return new Date().toISOString().slice(0, 7);
}
```

项目常用于：辅助函数（`getDefaultMonth`、`getGoalImpactText`）、事件处理函数（`handleSubmit`）。

### 3.2 异步函数（`async` / `await`）

```ts
async function loadAccounts() {
  const response = await fetch("/api/accounts");
  // ...
}
```

`await` 会暂停当前异步函数直到请求完成，但**不会卡住整个页面**。异步函数永远返回 Promise。

### 3.3 箭头函数

```ts
const handleChange = (value: string) => {
  setName(value);
};

// 简写：单行直接返回表达式
const double = (n: number) => n * 2;

// 无参数
() => { setOpen(false); }
```

箭头函数在项目里主要用于：回调（`onChange`、`onClick`）、`map` 的遍历函数、传给 `useState` 的更新函数。

### 3.4 回调函数（函数作为值传递）

```tsx
// 回调：把函数当作参数/属性传出去，由别人在合适时机调用
<button onClick={() => setOpen(false)}>关闭</button>

// 传给 setState 的函数式更新（见 20.4）
setAccounts((current) => [...current, newAccount]);
```

关键理解：回调函数不是「现在执行」，而是「定义好交给别人，将来调用」。`onClick={() => ...}` 里如果直接写 `onClick={setOpen(false)}` 就会立刻执行，而不是点击时执行——这是最常见的回调错误。

### 4.1 模板字符串（反引号）

```ts
const url = `/api/dashboard?month=${encodeURIComponent(month)}`;
```

## 5. 运算符：比较、三元、可选链、空值合并 ⭐

这些运算符在项目代码中出现频率极高，是读懂 JSX 里 `{}` 内容的基础。

### 5.1 比较与布尔运算

```ts
a === b    // 严格相等（项目只用 ===，不用 ==）
a !== b    // 严格不等
!isLoading // 取反
```



### 5.2 三元表达式

```ts
const label = isSubmitting ? "正在分析……" : "发送问题";
```

项目里三元大量用在 JSX 中：文案二选一、`className` 二选一、组件二选一。

### 5.3 可选链 `?.`

```ts
body.error.issues?.[0];   // issues 可能不存在，不存在时返回 undefined 而不报错
result?.baseline?.monthsToGoal; // 中间任何一层为空都返回 undefined
```

**为什么需要它**：后端返回的数据结构可能缺字段，直接 `.` 会抛 `Cannot read properties of undefined`。可选链让「可能为空」的读取安全返回 `undefined`。

### 5.4 空值合并 `??`

```ts
const message = firstIssue?.message ?? body.error.message; // 左边是 null/undefined 时用右边
const count = value ?? 0;
```

**关键区别**：`??` 只关心「空值」（`null`/`undefined`），而 `||` 关心「假值」（还包括 `0`、`""`、`false`）。需要保留合法的 `0`、`false`、空字符串时，必须用 `??`。例如 `savingsRate ?? "—"`：如果 `savingsRate` 是 `0`，`??` 会保留 `0`，`||` 会错误地显示 `"—"`。

### 5.5 短路运算 `&&`

```ts
error && <p>{error}</p>       // error 为真才渲染
isSubmitting && "保存中……"
```

`&&` 左侧为假值时，直接返回左侧值，右侧不执行——所以它可以当「条件成立才做」用。JSX 里 `&&` 是最常见的条件渲染写法（见 19.1）。

### 5.6 真值、假值与 `!!`

```ts
// 假值：false、0、""、null、undefined、NaN
// 真值：其他一切（包括空数组 []、空对象 {}）

const hasData = accounts.length > 0;  // 明确写成布尔，比 accounts.length 更清晰
const flag = !!value;                  // 双重取反：把任意值转成布尔
```

**注意**：`{count && <p>...</p>}` 当 `count` 是 `0` 时会渲染出 `"0"` 这个文本——所以条件尽量写成布尔，如 `accounts.length > 0`。

## 7. 数组：`map`、`filter` 与链式调用 ⭐

数组处理是前端日常的核心，`map` 尤其如此——JSX 列表渲染全靠它。

### 7.1 `map`：逐项转换

```ts
const doubled = [1, 2, 3].map((n) => n * 2); // [2, 4, 6]

// JSX 列表渲染（项目中最常见的写法）
{featureCards.map((feature) => (
  <Link key={feature.href} href={feature.href}>{feature.title}</Link>
))}
```

`map` 返回一个**新数组**，不修改原数组。回调的第二参数是下标：`items.map((item, index) => ...)`，项目里用于显示序号（`index + 1`）。

### 7.2 `filter`：保留符合条件的项

```ts
const readyRows = rows.filter((row) => !row.duplicate);
```



### 7.3 链式调用

```ts
const totals = rows
  .filter((row) => !row.duplicate)
  .map((row) => Number(row.amount));
```



### 7.4 JSX 列表与 `key`

```tsx
{accounts.map((account) => (
  <AccountCard key={account.id} account={account} />
))}
```

`key` **必须稳定且唯一**，一般用数据的 `id` 或不变字段（项目里用 `feature.href`、`message.id`）。不要用数组下标当 key——列表增删排序时，React 会按错误身份复用组件，导致状态错乱。只有列表永远不变时下标才可接受。

## 9. `Set`：保存不重复的值

```ts
const [selectedRows, setSelectedRows] = useState<Set<number>>(new Set());

// 更新时创建副本，再增删
setSelectedRows((current) => {
  const next = new Set(current);
  if (next.has(rowNumber)) {
    next.delete(rowNumber);
  } else {
    next.add(rowNumber);
  }
  return next;
});
```

**为什么用 Set 而不是数组**：导入 CSV 的「勾选行」需要快速判断某行是否选中（`has`），且天然去重。注意两点：`Set` 的内容**不能用索引访问**，判断存在用 `has`；更新时永远基于副本（`new Set(current)`），符合 React 不可变更新要求。

项目位置：`app/import/page.tsx`（CSV 行勾选）。

## 10. 异步、Promise 与错误处理 ⭐

前端请求天然是异步的，这一章是「能写交互页面」的门槛。

### 10.1 `async` / `await`

```ts
async function requestData() {
  const response = await fetch("/api/example");
  const body = await response.json();
  return body;
}
```

「等待」只暂停当前异步函数，不会把整个浏览器页面卡死。

### 10.2 `try / catch / finally`

```ts
try {
  setIsLoading(true);
  const result = await requestData();
  setData(result);
} catch (error) {
  setError(
    error instanceof Error
      ? error.message
      : "发生未知错误",
  );
} finally {
  setIsLoading(false);
}
```

- `try`：可能失败的流程。
- `catch`：处理抛出的错误。
- `finally`：**成功或失败都会执行**，适合解除 loading 和锁——这是项目里表单提交的标准套路（见 24.2）。



### 10.3 主动抛错和自定义错误

```ts
// 业务失败主动抛错
if (!response.ok) {
  throw new Error("请求失败");
}

// 自定义错误类：用 instanceof 区分错误来源
class DashboardFetchError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "DashboardFetchError";
  }
}
```

捕获后区分：

```ts
const message =
  error instanceof DashboardFetchError
    ? error.message
    : "无法连接服务器";
```

**为什么自定义错误类**：不同的失败原因要展示不同的文案。页面里 `error instanceof DashboardFetchError` 判断是「服务器返回了异常结构」还是「网络断了」，分别处理。

### 10.4 Promise 链（项目里少用，但要能读懂）

```ts
loadData()
  .then((data) => setData(data))
  .catch((error) => setError(error.message));
```



### 10.5 `void loadData()`

```ts
useEffect(() => {
  async function loadData() {
    // ...
  }
  void loadData(); // 在 effect 内部调用 async 函数，void 表示忽略返回的 Promise
}, []);
```

`useEffect` 的主体不能直接 `await`（React 要求清理函数同步返回），所以项目把 async 函数定义在 effect 内部，再用 `void` 调用。`void` 只是告诉读者「这个 Promise 的错误已在内部处理」，不写也能跑。

项目位置：`app/dashboard/page.tsx`（`fetchDashboard` 封装 + 自定义错误类）、`app/goals/page.tsx`（最简洁的表单提交）。


## 20. `useState`：保存影响画面的状态 ⭐



### 20.1 基本模板

```tsx
const [name, setName] = useState("");          // 文本输入框
const [isSubmitting, setIsSubmitting] = useState(false); // 提交中标志
const [error, setError] = useState("");        // 错误信息
```

`useState(初始值)` 返回 `[值, 修改函数]`，用数组解构接收。修改函数命名规则：`set` + 状态名。**调用修改函数不会立刻改变变量的值**，而是标记「下次渲染用新值」——这就是为什么不能指望 `setName(name)` 之后马上读 `name`。

项目约定：表单输入统一存字符串（哪怕用户输入的是数字），提交时再 `Number()` 转换，避免输入框类型转换问题。

### 20.2 显式泛型

```tsx
const [accounts, setAccounts] = useState<Account[]>([]);
const [result, setResult] = useState<SavingsGoalResult | null>(null);
const [selectedRows, setSelectedRows] = useState<Set<number>>(new Set());
```



### 20.3 函数初始值（惰性初始化）

```tsx
const [month, setMonth] = useState(getDefaultMonth);   // 传函数名，不调用
```

传函数名时 React **只在首次渲染执行一次**；如果写 `useState(getDefaultMonth())`，每次渲染都会调用函数，浪费。项目里 `getDefaultMonth` 就是这样用的（`app/dashboard/page.tsx`）。

### 20.4 基于旧状态更新（函数式更新）

```tsx
setAccounts((current) => [...current, createdAccount]);        // 追加
setMessages((current) => [...current, userMessage]);           // 追加
setQuestion((current) => (current.length === 0 ? submittedQuestion : current)); // 条件更新
```

**更新依赖旧值时必须传函数**，参数 `current` 是当前最新值。直接写 `setAccounts([...accounts, newAccount])` 在快速连续更新时可能读到旧值（闭包问题）。同时满足「要算新值」和「要用最新值」时，函数式更新是标准答案。

## 21. React 状态的不可变更新 ⭐

**铁律：绝不直接修改 state 持有的数组、对象、Set——永远创建新值再 set。** 直接修改（`accounts.push(...)`）React 无法感知变化，界面不会更新。

### 21.1 数组末尾追加

```ts
setAccounts((current) => [...current, createdAccount]);
```



### 21.2 替换数组中的一项

```ts
setPreviewRows((current) =>
  current.map((row) =>
    row.rowNumber === rowNumber ? { ...row, category } : row
  )
);
```



### 21.3 删除数组中的一项

```ts
setPreviewRows((current) => current.filter((row) => row.rowNumber !== rowNumber));
```



### 21.4 更新 Set

```ts
setSelectedRows((current) => {
  const next = new Set(current); // 副本
  if (next.has(rowNumber)) {
    next.delete(rowNumber);
  } else {
    next.add(rowNumber);
  }
  return next;
});
```

记忆方法：**数组用** `map`**/**`filter`**/展开造新数组，对象用展开造新对象，Set 用** `new Set(current)` **造副本**——三步套路「副本 → 修改 → 返回」。

## 22. `useEffect`：副作用与清理 ⭐



### 22.1 完整模板

```tsx
useEffect(
  () => {
    // 主体：发请求、订阅、操作 DOM...
    return () => {
      // 清理：取消请求、取消订阅...
    };
  },
  [依赖1, 依赖2]
);
```

执行时机：

- 挂载后：执行主体。
- 依赖变化后：先执行上次的清理，再执行新主体。
- 卸载时：执行最后一次清理。



### 22.2 依赖数组的形式


| 写法                     | 执行时机                   |
| ---------------------- | ---------------------- |
| `[]`（空数组）              | 只在挂载后执行一次；清理只在卸载时执行    |
| `[month, trendMonths]` | 首次执行；任一依赖变化时：先清理，再重新执行 |
| 不传第二个参数                | 每次渲染后都执行（项目未用，少用）      |




### 22.3 不要把 Effect 主体直接写成 `async`

```tsx
useEffect(() => {
  async function loadAccounts() {
    try {
      const response = await fetch("/api/accounts");
      const data = await response.json();
      if (!cancelled) {
        setAccounts(data.data.accounts);
      }
    } catch {
      // 静默
    } finally {
      if (!cancelled) {
        setIsAccountsLoading(false);
      }
    }
  }

  void loadAccounts(); // async 函数定义在内部，再调用

  return () => {
    cancelled = true; // 清理：卸载时置 true
  };
}, []);
```

React 不允许 effect 主体直接是 async（清理函数必须同步返回），所以项目一律「effect 内部定义 async 函数 + `void 调用()`」。

### 22.4 用布尔标记忽略过期结果

`cancelled` 标志是项目的标准写法：请求是异步的，响应回来时组件可能已卸载或依赖已变化，用标志避免「在已卸载的组件上 setState」，也避免旧请求的结果覆盖新状态。

### 22.5 用 `AbortController` 取消 fetch

```tsx
useEffect(() => {
  const controller = new AbortController();

  async function loadDashboard() {
    setIsDashboardLoading(true);
    setDashboardError("");
    try {
      const result = await fetchDashboard(month, trendMonths, controller.signal);
      if (!controller.signal.aborted) {
        setDashboardResult(result);
      }
    } catch (error) {
      if (controller.signal.aborted) {
        return; // 被取消的请求不报错
      }
      setDashboardError(
        error instanceof DashboardFetchError
          ? error.message
          : "仪表盘数据加载失败，请稍后重试。"
      );
    } finally {
      if (!controller.signal.aborted) {
        setIsDashboardLoading(false);
      }
    }
  }

  void loadDashboard();

  return () => {
    controller.abort(); // 清理：取消进行中的请求
  };
}, [month, trendMonths]);
```

fetch 传 `{ signal: controller.signal }`，被 abort 时 fetch 会 reject 成 `AbortError`。判断方式（`app/history/page.tsx`）：

```ts
if (caughtError instanceof DOMException && caughtError.name === "AbortError") {
  return;
}
```

**这个模式的意义**：快速切换筛选条件时，旧请求不会覆盖新数据。

### 22.6 依赖变化时取消旧请求

结合 22.5：依赖变化 → 先执行清理（abort 旧请求）→ 再执行新主体（发起新请求）。dashboard 页还配合 `useRef` 保存控制器，供外部函数主动取消（见 23.3）。

### 22.7 开发环境可能额外执行一次

React 18+ 开发模式下，StrictMode 会「挂载 → 卸载 → 再挂载」，effect 看起来执行了两次。这是正常的，不要为了消除它写奇怪的代码；生产环境只执行一次。

## 23. `useRef`：DOM 引用和不触发渲染的可变值 ⭐



### 23.1 DOM Ref

```tsx
const messagesEndRef = useRef<HTMLDivElement>(null);

<div ref={messagesEndRef} />

useEffect(() => {
  messagesEndRef.current?.scrollIntoView({
    behavior: "smooth",
    block: "end",
  });
}, [messages, isSubmitting]);
```

泛型 `HTMLDivElement` 对应元素类型（`HTMLInputElement`、`HTMLTextAreaElement` 同理）。子组件接收 ref 时用 `RefObject<HTMLDivElement | null>` 类型（React 19 写法，`ChatMessageList` 的 props）。

### 23.2 防重复提交锁

```tsx
const submissionLockRef = useRef(false);

// 提交前：
if (submissionLockRef.current) {
  return; // 已在提交中，直接忽略
}
submissionLockRef.current = true;
setIsSubmitting(true);

// ... await fetch ...

// finally 里：
submissionLockRef.current = false;
setIsSubmitting(false);
```

**为什么需要 ref 而不是 state 当锁**：`setState` 是异步的，提交处理函数里 `setIsSubmitting(true)` 后立刻判断 `isSubmitting` 还是旧值，锁会失效。ref 的值在渲染之间**同步**可变，适合当标志。项目里 chat 页（`submissionLockRef`）和 import 页（`importLockRef`）都这么用。

### 23.3 保存上一个请求控制器

```tsx
const abortRef = useRef<AbortController | null>(null);

// 新请求发起前，先取消上一个
if (abortRef.current) {
  abortRef.current.abort();
}
const controller = new AbortController();
abortRef.current = controller;
```

dashboard 页的「刷新按钮」就是通过这个 ref 主动取消正在进行的请求（`refreshDashboard`）。

### 23.4 state 与 ref


|          | state   | ref                  |
| -------- | ------- | -------------------- |
| 变化会触发渲染  | ✓       | ✗                    |
| 值在渲染之间保留 | ✓       | ✓                    |
| 读取是同步的   | ✗       | ✓                    |
| 用途       | 影响画面的数据 | DOM 引用、锁、控制器等「外部」可变值 |




## 24. 表单与事件 ⭐



### 24.1 受控输入框

「受控」= 输入框的值由 state 决定，用户输入时通过 `onChange` 更新 state：

```tsx
const [name, setName] = useState("");

<label className="block">
  <span className="text-sm font-medium text-gray-700">账户名称</span>
  <input
    value={name}
    onChange={(event) => setName(event.target.value)}
    placeholder="例如：工资卡"
  />
</label>
```

`value` **必须和 state 一一对应**，否则输入框不会更新。`event.target.value` 永远是字符串；需要数字时 `Number()` 转换。

### 24.2 表单提交（完整套路）

```tsx
async function handleSubmit(event: FormEvent<HTMLFormElement>) {
  event.preventDefault();        // ① 阻止整页刷新
  setError("");                  // ② 清空上次错误
  if (submissionLockRef.current) return; // ③ 防重复提交（可选，重要页面用）
  submissionLockRef.current = true;
  setIsSubmitting(true);         // ④ 进入提交中

  try {
    const response = await fetch("/api/scenarios", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        name,
        currentAmount,
        targetAmount,
      }),
    });

    const body = await response.json();

    if (!body.ok) {              // ⑤ 业务失败（见 28.2）
      const firstIssue = body.error.issues?.[0];
      setError(firstIssue?.message ?? body.error.message);
      return;
    }

    setResult(body.data.calculation);
  } catch {
    setError("场景计算失败，请稍后重试。");
  } finally {
    setIsSubmitting(false);      // ⑥ 无论成败都恢复
    submissionLockRef.current = false;
  }
}

<form onSubmit={handleSubmit}>
  <input value={name} onChange={(event) => setName(event.target.value)} disabled={isSubmitting} />
  {error && <p role="alert">{error}</p>}
  <button type="submit" disabled={isSubmitting || name.trim().length === 0}>
    {isSubmitting ? "保存中……" : "保存"}
  </button>
</form>
```

**背诵这个套路**（项目里每个表单页都一样）：`preventDefault` → 清错误 → 上锁 + `setIsSubmitting(true)` → `try/fetch/catch/finally`（finally 里恢复 submitting 和解锁）。提交按钮用 `disabled={isSubmitting || ...}` 双重防重复。

## 27. `fetch` GET 请求



### 27.1 URL 查询参数


`encodeURIComponent` 转义特殊字符，防止破坏 URL。

### 27.2 `response.ok` 与 `body.ok`（两层判断）

```ts
const response = await fetch(url);     // ① HTTP 层：网络是否成功
if (!response.ok) { throw new Error("请求失败"); }

const body = await response.json();    // ② 业务层：接口是否成功
if (!body.ok) { throw new Error(body.error.message); }
```

**项目 API 的统一响应结构**：`{ ok: boolean, data?: ..., error?: { message, issues? } }`。HTTP 200 不代表业务成功——业务失败时 HTTP 状态码可能仍是 200，必须检查 `body.ok`。**不能只靠** `response.ok` **判断业务成功。**

## 29. Zod：运行时校验响应 ⭐



### 29.1 定义成功和失败结构

```ts
// schemas/dashboard.ts
import { z } from "zod";

export const dashboardApiResponseSchema = z.discriminatedUnion("ok", [
  z.object({
    ok: z.literal(true),
    data: z.object({
      accounts: z.array(accountSchema),
      // ...
    }),
  }),
  z.object({
    ok: z.literal(false),
    error: z.object({
      message: z.string(),
    }),
  }),
]);
```

用 `discriminatedUnion("ok", ...)` 定义「成功/失败」两种响应结构，靠 `ok` 字段判别。类型用 `z.infer` 同步导出（见 16.2）。

### 29.2 `safeParse`（校验封装）

```tsx
class DashboardFetchError extends Error {
  name = "DashboardFetchError";
}

async function fetchDashboard(
  month: string,
  months: number,
  signal: AbortSignal,
): Promise<DashboardResult> {
  const response = await fetch(url, { signal });

  let body: unknown;                       // ① 先读成 unknown
  try {
    body = await response.json();
  } catch {
    throw new DashboardFetchError("服务器返回了无法读取的响应。");
  }

  const parsed = dashboardApiResponseSchema.safeParse(body); // ② zod 校验
  if (!parsed.success) {
    throw new DashboardFetchError("服务器返回的数据结构不符合预期。");
  }

  if (!parsed.data.ok) {
    throw new DashboardFetchError(parsed.data.error.message); // ③ 业务错误
  }

  return parsed.data.data;
}
```

**为什么需要 zod 而不是** `as`：`as` 只是告诉 TypeScript「相信我」，运行时数据结构错了照样崩；`safeParse` 在运行时真正检查每个字段，返回 `{ success: true/false }`，失败时结构错误会被拦截成可读的错误信息。**接口响应永远先** `unknown`**，再** `safeParse`**。**

项目位置：`app/dashboard/page.tsx`（完整封装）、`schemas/` 目录。

## 35. 客户端数据页完整骨架 ⭐

把前面所有核心知识拼成一个完整页面（dashboard 页的结构）：

```tsx
"use client";

import { useEffect, useRef, useState } from "react";
import type { DashboardResult } from "@/types/finance";
import { dashboardApiResponseSchema } from "@/schemas/dashboard";

function getDefaultMonth() {
  return new Date().toISOString().slice(0, 7); // "2026-08"
}

class DashboardFetchError extends Error {
  name = "DashboardFetchError";
}

async function fetchDashboard(
  month: string,
  months: number,
  signal: AbortSignal,
): Promise<DashboardResult> {
  const response = await fetch(
    `/api/dashboard?month=${encodeURIComponent(month)}&months=${months}`,
    { signal },
  );

  const body: unknown = await response.json();
  const parsed = dashboardApiResponseSchema.safeParse(body);

  if (!parsed.success) {
    throw new DashboardFetchError("服务器返回的数据结构不符合预期。");
  }
  if (!parsed.data.ok) {
    throw new DashboardFetchError(parsed.data.error.message);
  }
  return parsed.data.data;
}

export default function DashboardPage() {
  const [month, setMonth] = useState(getDefaultMonth);   // 惰性初始化
  const [trendMonths, setTrendMonths] = useState(6);
  const [result, setResult] = useState<DashboardResult | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState("");
  const abortRef = useRef<AbortController | null>(null); // 供刷新按钮取消请求

  useEffect(() => {
    if (abortRef.current) {
      abortRef.current.abort();        // 依赖变化 → 先取消旧请求
    }
    const controller = new AbortController();
    abortRef.current = controller;

    let cancelled = false;

    async function load() {
      setIsLoading(true);
      setError("");
      try {
        const data = await fetchDashboard(month, trendMonths, controller.signal);
        if (!cancelled && !controller.signal.aborted) {
          setResult(data);
        }
      } catch (caughtError) {
        if (cancelled || controller.signal.aborted) return;
        setError(caughtError instanceof DashboardFetchError
          ? caughtError.message
          : "仪表盘数据加载失败，请稍后重试。");
      } finally {
        if (!cancelled && !controller.signal.aborted) {
          setIsLoading(false);
        }
      }
    }

    void load();

    return () => {
      cancelled = true;
      controller.abort();
    };
  }, [month, trendMonths]);

  function refreshDashboard() {
    abortRef.current?.abort();         // 主动取消进行中的请求
    setIsLoading(true);
  }

  return (
    <main className="min-h-screen bg-gray-50 px-6 py-8">
      <div className="mx-auto max-w-5xl">
        <h1 className="text-2xl font-bold text-gray-900">仪表盘</h1>

        {isLoading && <p>正在加载...</p>}
        {!isLoading && error && <p role="alert">{error}</p>}
        {!isLoading && !error && result && (
          <section>
            {/* 数据渲染：组件、图表、列表 */}
          </section>
        )}
      </div>
    </main>
  );
}
```

```tsx
  const [error, setError] = useState("");
  const submitLockRef = useRef(false);

  async function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    setError("");
    if (submitLockRef.current) return;
    submitLockRef.current = true;
    setIsSubmitting(true);

    try {
      const response = await fetch("/api/example", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ name }),
      });
      const body = await response.json();

      if (!body.ok) {
        throw new Error(body.error.message);
      }
      setName("");
    } catch (caughtError) {
      setError(
        caughtError instanceof Error ? caughtError.message : "无法连接服务器",
      );
    } finally {
      submitLockRef.current = false;
      setIsSubmitting(false);
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="name">名称</label>
      <input
        id="name"
        value={name}
        onChange={(event) => setName(event.target.value)}
        disabled={isSubmitting}
      />

      {error && <p role="alert">{error}</p>}

      <button
        type="submit"
        disabled={isSubmitting || name.trim().length === 0}
      >
        {isSubmitting ? "保存中……" : "保存"}
      </button>
    </form>
  );
}
```

## 附：项目中反复出现的固定套路（背诵清单）

1. **表单提交套路**：`preventDefault` → 清错误 → 上锁 + `setIsSubmitting(true)` → try/fetch/catch/finally（finally 里恢复 submitting 并解锁）。
2. **加载数据套路**：`useEffect` + 内部 async 函数 + `void 调用()` + 清理函数（cancelled 标志或 `controller.abort()`）。
3. **错误展示套路**：`error` 状态 + `{error && <p role="alert">}`；取值用 `具体消息 ?? 通用消息 ?? 兜底文案`。
4. **空状态套路**：`if (长度 === 0) return <空状态组件 />` 放在组件开头。
5. **受控表单套路**：value 来自 state，onChange 用 `setXxx(e.target.value)`；子组件通过 `onXxxChange` props 上报。
6. **防重复提交**：`useRef(false)` 上锁，`finally` 解锁。
7. **JSON 接口响应格式**：`{ ok: true, data }` / `{ ok: false, error: { message } }`，前端先查 `ok`。
8. **不可变更新**：数组用 `map`/`filter`/展开，对象用展开，Set 用 `new Set(current)` 副本。
9. **请求四态渲染**：`isLoading` / `error` / 空数据 / 有数据，四个 `&&` 块并列互斥。

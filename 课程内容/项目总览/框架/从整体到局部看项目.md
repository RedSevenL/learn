# 讲解大纲：从整体到局部看 ai-finance-cfo

> 目的：把一个全栈项目"从整体到局部"讲清楚，看完能口头复述整个项目，尤其是前端。
> 风格：简练、大白话。

## 第 1 部分 一页看懂整个项目（全局观）

用一张图把整个项目装进脑子，先有整体再有细节：

```txt
用户在浏览器里用 7 个页面
        │
        ▼
Next.js 应用（前端 + 后端同在一个项目里）
        │
   ┌────┴─────┐
   │          │
 前端页面      API 接口
 React 组件    Route Handler
   │          │
   └────┬─────┘
        ▼
    三类后台
  ┌─────┼──────────────┐
  │     │              │
确定性计算    数据库        DeepSeek AI
(钱怎么算)   SQLite      (只负责理解问题)
```

这节要讲清楚：

- 这是"一个项目、两种身份"：同一个 Next.js 项目里既有前端页面也有后端接口。
- 项目的灵魂原则：**AI 只负责听懂人话，钱全部由代码算**。
- 数据全部存在本地 SQLite，天然隐私，无部署成本。
- 一句话版本：**7 个页面 + 一堆 API + 本地数据库 + 一个 AI 帮手**。

## 第 2 部分 全局骨架：页面、布局、数据怎么流（前端重点）

项目先搭骨架，再填血肉。这节讲"骨架"：

- **一个总布局管全站**：`layout.tsx` 里定义了顶部导航栏（7 个入口），所有页面共用这一个壳子。
- **7 个页面各管一件事**，先认门，知道它们各自是干什么的：
  - `/` 首页：功能入口展示，纯展示，不碰数据。
  - `/dashboard` 仪表盘：账户管理 + 财务指标 + 图表。
  - `/chat` AI 对话：自然语言问财务问题。
  - `/goals` 储蓄目标：手动填参数做复利计算。
  - `/scenarios` 场景模拟：改一个参数对比"有/没有"的差别。
  - `/import` CSV 导入：把账单文件导进系统。
  - `/history` 计算历史：回看以前的 AI 计算过程。
- **前端组件分两层**：页面（`app/*/page.tsx`）负责"调度"，小组件（`components/*/`）负责"干活"。
- **数据流向一条线**：页面 → `fetch` 调 API → 拿到 JSON → 本地校验 → 渲染。
- **页面两种身份**：服务端组件（默认，不写交互）和客户端组件（`"use client"`，React 状态、交互都在这里）。
- **所有代码一行一行数得完**：全部代码约 11500 行，不是庞然大物，可整体复述。

## 第 3 部分 核心页面逐个拆（前端重点）

### 3.1 仪表盘 `/dashboard` —— 项目的"客厅"

- 一个页面管三件事：**账户管理 + 核心指标 + 两张图表**。
- 打开时自动用当前月份做基准，选月份、选区间会重新请求数据。
- 数据全靠一个接口：`fetch("/api/dashboard?month=...&months=...")`，前端拿回来渲染。
- 组件拆得很细：`AccountForm`（新增）、`AccountList`（列表）、`DashboardMetrics`（指标卡片）、`CashFlowTrendChart`（现金流趋势图）、`CategoryExpenseChart`（分类支出图）、`DashboardEmptyState`（没数据时的引导）。
- 学习要点：**一个复杂页面 = 一块一块小组件拼起来**，这也是复述项目时最好讲的部分。

### 3.2 AI 对话 `/chat` —— 项目的"AI 面"

- 打开就有欢迎语，输入问题点发送。
- 前端做的事：维护消息列表（存在 React 内存里，刷新就没了）、发请求、把返回结果渲染成卡片（`ChatCalculationCard` 专门展示假设和计算步骤）。
- 后端做的事：把问题发给 DeepSeek → 得到"意图" → 本地代码算钱 → 返回结果。
- 学习要点：**前端只管"收集和展示"，AI 和后端在它看不到的地方干活**。

### 3.3 CSV 导入 `/import` —— 前端状态最重的页面

- 全程没有后端计算，都是前端一步步处理：选文件 → 解析 → 猜字段映射 → 预览 → 确认 → 提交。
- 状态机式的流程：文件阶段 → 映射阶段 → 预览阶段 → 汇总阶段，一步一步往下走。
- 组件对应流程的每一步：`CsvFilePicker` → `CsvFieldMappingForm` → `CsvPreviewTable` → `CsvImportSummary`。
- 学习要点：**一个页面怎么用状态管理把一个长流程切成几步**，这是前端面试/项目里很典型的东西。

### 3.4 其他三个页面（一页一个功能）

- `/goals` 储蓄目标：手动填参数，调后端接口计算，展示结果 + 计算步骤。
- `/scenarios` 场景模拟：调一个参数，对比"原来 vs 改了之后"，结论用大白话（推迟/提前几个月）。
- `/history` 计算历史：从后端拉历史记录，回看以前问过什么、算过什么。

## 第 4 部分 后端的"半边天"（了解即可）

- **API 是什么**：前端 `fetch` 的网址背后，是 `app/api/*/route.ts` 里的一段段函数。
- **核心模式**：请求进来 → 校验数据（Zod）→ 查数据库 → 确定性计算 → 返回 JSON。
- **两大铁律**：
  1. 入口处用 Zod 校验，格式不对直接拒绝。
  2. 钱用 Decimal.js 算，绝不用普通浮点数，避免精度错误。
- 主要接口：账户、流水、负债、CSV 导入、仪表盘、储蓄目标、场景、Chat、计算历史。
- 数据库就一张张表：账户、流水、负债、计算历史，存在本地 SQLite 文件里。

## 第 5 部分 把 AI 装进去：DeepSeek 只在"听懂"环节出现（了解即可）

- **AI 的位置非常小**：不碰数字，只做"意图解析"。
- 完整流程：用户问"我两年能攒够 50 万吗" → 发给 DeepSeek → 返回一个结构化意图（目标金额、年限、月供）→ 本地代码用真实账户数据计算 → 算出结果保存并展示。
- **为什么这么设计**：财务数字必须可追溯、可复现，AI 算数不靠谱，所以 AI 只当"翻译官"。
- **计算留痕**：每次计算都存下输入、公式版本、步骤和结果，所以有 `/history` 页面。

## 第 6 部分 一张时间线串起来 + 三个"记住它就够了"

- 项目怎么一步步长出来的：环境 → 基础练习 → React → 页面骨架 → 数据库 → 计算引擎 → AI → 完整功能 → 验收。
- **复述时的三句话**：
  1. 这是一个本地优先的个人财务应用，7 个页面、数据和 AI 都围着"个人财务"转。
  2. 前端拆成"页面 + 小组件"，每个页面一个功能，复杂页面（仪表盘、导入）是组件拼出来的。
  3. AI 只理解问题，钱全部由确定性代码计算，结果可追溯。

## 二、为什么需要整理代码

刚开始学习时，把代码都写在 `app/page.tsx` 里是可以的。

这样好处是：

- 文件少。
- 容易看到完整流程。
- 适合初学阶段理解 React。

但项目变大后，这种写法会出现问题：

- 页面文件越来越长。
- 类型定义到处复制。
- 假数据散落在多个文件。
- 组件职责不清楚。
- 后面接 API 时不知道该改哪里。

所以阶段二复盘的重点不是写新功能，而是整理结构。

整理后的目标是：

```txt
页面负责组织数据和布局
组件负责展示局部 UI
类型负责描述数据结构
假数据集中放在一个地方
```

这能让后续开发更稳定。

## 四、抽取 Account 类型

前面课程中，我们可能在页面文件里直接写：

```tsx
type Account = {
  id: string;
  name: string;
  type: "cash" | "bank" | "credit" | "investment";
  balance: number;
};
```

如果多个组件都需要这个类型，建议抽到单独文件。

创建：

```txt
types/finance.ts
```

写入：

```ts
export type AccountType = "cash" | "bank" | "credit" | "investment";

export type Account = {
  id: string;
  name: string;
  type: AccountType;
  balance: number;
};
```

这样其他文件可以导入：

```tsx
import type { Account } from "@/types/finance";
```

注意这里用了：

```tsx
import type
```

它表示只导入 TypeScript 类型，不导入运行时代码。

初学阶段不强制，但这是一个好习惯。

- 不同页面可以复用同一份假数据。

## 七、拆出 AccountCard

创建：

```txt
components/accounts/AccountCard.tsx
```

写入：

```tsx
import type { Account } from "@/types/finance";

type AccountCardProps = {
  account: Account;
};

function getAccountTypeLabel(type: Account["type"]) {
  if (type === "bank") {
    return "银行卡";
  }

  if (type === "cash") {
    return "现金";
  }

  if (type === "credit") {
    return "信用卡";
  }

  return "投资账户";
}

export function AccountCard({ account }: AccountCardProps) {
  return (
    <div className="rounded-lg border border-gray-200 bg-white p-4 shadow-sm">
      <div className="flex items-start justify-between gap-4">
        <div>
          <h3 className="font-semibold text-gray-900">{account.name}</h3>
          <p className="mt-1 text-sm text-gray-500">
            类型：{getAccountTypeLabel(account.type)}
          </p>
        </div>

        <p className="text-right text-lg font-semibold text-gray-900">
          {account.balance.toLocaleString()} 元
        </p>
      </div>
    </div>
  );
}
```

这个组件只负责一件事：

> 展示单个账户。

它不负责：

- 保存账户列表。
- 新增账户。
- 表单校验。
- 从 API 获取数据。

组件职责越清楚，后面越好维护。

## 九、拆出 AccountList

创建：

```txt
components/accounts/AccountList.tsx
```

写入：

```tsx
import type { Account } from "@/types/finance";
import { AccountCard } from "./AccountCard";
import { EmptyAccounts } from "./EmptyAccounts";

type AccountListProps = {
  accounts: Account[];
};

export function AccountList({ accounts }: AccountListProps) {
  if (accounts.length === 0) {
    return <EmptyAccounts />;
  }

  return (
    <section className="space-y-3">
      {accounts.map((account) => (
        <AccountCard key={account.id} account={account} />
      ))}
    </section>
  );
}
```

这个组件负责：

- 判断账户列表是否为空。
- 有数据时渲染多个 `AccountCard`。
- 没数据时渲染 `EmptyAccounts`。

它的数据来自 props：

```tsx
type AccountListProps = {
  accounts: Account[];
};
```

这说明：

> `AccountList` 不自己创造账户数据，它只接收数据并展示。

## 十一、拆出 AccountForm

账户表单稍微复杂一些。

它需要接收：

- 表单字段值。
- 修改字段的函数。
- 错误信息。
- 提交函数。
- 是否提交中。

创建：

```txt
components/accounts/AccountForm.tsx
```

写入：

```tsx
import type { Account } from "@/types/finance";
import { ErrorMessage } from "./ErrorMessage";

type AccountFormProps = {
  name: string;
  type: Account["type"];
  balance: string;
  error: string;
  isSubmitting: boolean;
  onNameChange: (value: string) => void;
  onTypeChange: (value: Account["type"]) => void;
  onBalanceChange: (value: string) => void;
  onSubmit: (event: React.FormEvent<HTMLFormElement>) => void;
};

export function AccountForm({
  name,
  type,
  balance,
  error,
  isSubmitting,
  onNameChange,
  onTypeChange,
  onBalanceChange,
  onSubmit
}: AccountFormProps) {
  return (
    <section className="rounded-lg border border-gray-200 bg-white p-6 shadow-sm">
      <h2 className="text-lg font-semibold text-gray-900">新增账户</h2>
      <p className="mt-1 text-sm text-gray-500">
        当前先用本地状态保存，后续课程会接入 API 和数据库。
      </p>

      <form onSubmit={onSubmit} className="mt-6 space-y-4">
        <label className="block">
          <span className="text-sm font-medium text-gray-700">账户名称</span>
          <input
            value={name}
            onChange={(event) => onNameChange(event.target.value)}
            placeholder="例如：工资卡"
            className="mt-1 w-full rounded-md border border-gray-300 px-3 py-2 text-sm outline-none focus:border-gray-900 focus:ring-2 focus:ring-gray-200"
          />
        </label>

        <label className="block">
          <span className="text-sm font-medium text-gray-700">账户类型</span>
          <select
            value={type}
            onChange={(event) =>
              onTypeChange(event.target.value as Account["type"])
            }
            className="mt-1 w-full rounded-md border border-gray-300 px-3 py-2 text-sm outline-none focus:border-gray-900 focus:ring-2 focus:ring-gray-200"
          >
            <option value="bank">银行卡</option>
            <option value="cash">现金</option>
            <option value="credit">信用卡</option>
            <option value="investment">投资账户</option>
          </select>
        </label>

        <label className="block">
          <span className="text-sm font-medium text-gray-700">账户余额</span>
          <input
            value={balance}
            onChange={(event) => onBalanceChange(event.target.value)}
            placeholder="例如：20000"
            className="mt-1 w-full rounded-md border border-gray-300 px-3 py-2 text-sm outline-none focus:border-gray-900 focus:ring-2 focus:ring-gray-200"
          />
        </label>

        {error && <ErrorMessage message={error} />}

        <button
          type="submit"
          disabled={isSubmitting}
          className="rounded-md bg-gray-900 px-4 py-2 text-sm font-medium text-white hover:bg-gray-700 disabled:cursor-not-allowed disabled:bg-gray-400"
        >
          {isSubmitting ? "提交中..." : "新增账户"}
        </button>
      </form>
    </section>
  );
}
```

这里有几行类型看起来比较抽象：

```tsx
onNameChange: (value: string) => void;
onSubmit: (event: React.FormEvent<HTMLFormElement>) => void;
```

可以这样读：

| 写法 | 含义 |
| --- | --- |
| `(value: string) => void` | 接收一个字符串参数，不返回结果的函数 |
| `(event: React.FormEvent<HTMLFormElement>) => void` | 接收一个表单提交事件，不返回结果的函数 |

这里的 `void` 表示：

> 这个函数主要是做一件事，不需要把结果 return 出来。

比如 `setName("工资卡")` 会更新状态，但它本身不需要返回一个值。

这里的 props 比较多。

这是正常的。

因为 `AccountForm` 是一个受控表单组件：

```txt
字段值由父组件传入
用户输入后调用父组件传入的函数
父组件更新状态
状态再传回表单
```

## 十二、整理页面代码

现在可以让页面文件变得更短。

假设账户管理暂时放在首页或某个页面里，页面代码可以变成：

```tsx
"use client";

import { useState } from "react";
import { AccountForm } from "@/components/accounts/AccountForm";
import { AccountList } from "@/components/accounts/AccountList";
import { initialAccounts } from "@/lib/mock-data";
import type { Account } from "@/types/finance";

export default function AccountsPage() {
  const [accounts, setAccounts] = useState<Account[]>(initialAccounts);
  const [name, setName] = useState("");
  const [type, setType] = useState<Account["type"]>("bank");
  const [balance, setBalance] = useState("");
  const [error, setError] = useState("");
  const [isSubmitting, setIsSubmitting] = useState(false);

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();

    const trimmedName = name.trim();
    const numericBalance = Number(balance);

    if (trimmedName.length === 0) {
      setError("请输入账户名称。");
      return;
    }

    if (!Number.isFinite(numericBalance)) {
      setError("请输入合法的账户余额。");
      return;
    }

    setIsSubmitting(true);

    const newAccount: Account = {
      id: `account_${Date.now()}`,
      name: trimmedName,
      type,
      balance: numericBalance
    };

    setAccounts([...accounts, newAccount]);
    setName("");
    setType("bank");
    setBalance("");
    setError("");
    setIsSubmitting(false);
  }

  return (
    <main className="min-h-screen bg-gray-50 px-6 py-8">
      <div className="mx-auto max-w-4xl">
        <header className="mb-8">
          <p className="text-sm font-medium text-gray-500">Accounts</p>
          <h1 className="mt-2 text-3xl font-bold text-gray-900">账户管理</h1>
          <p className="mt-2 text-sm text-gray-600">
            新增账户，并查看当前账户列表。
          </p>
        </header>

        <AccountForm
          name={name}
          type={type}
          balance={balance}
          error={error}
          isSubmitting={isSubmitting}
          onNameChange={setName}
          onTypeChange={setType}
          onBalanceChange={setBalance}
          onSubmit={handleSubmit}
        />

        <section className="mt-8">
          <div className="mb-4">
            <h2 className="text-lg font-semibold text-gray-900">账户列表</h2>
            <p className="mt-1 text-sm text-gray-500">
              当前共有 {accounts.length} 个账户。
            </p>
          </div>

          <AccountList accounts={accounts} />
        </section>
      </div>
    </main>
  );
}
```

你会发现页面仍然负责状态和提交逻辑。

组件负责展示和触发事件。

这是一种很常见的前端结构。

## 十三、理解页面到组件的数据流

现在的数据流可以画成：

```txt
AccountsPage
  ├── 状态：accounts、name、type、balance、error
  ├── 函数：handleSubmit、setName、setType、setBalance
  │
  ├── AccountForm
  │     ├── 接收 name、type、balance、error
  │     └── 调用 onNameChange、onTypeChange、onBalanceChange、onSubmit
  │
  └── AccountList
        └── 接收 accounts
              └── AccountCard
                    └── 接收 account
```

更简化地说：

```txt
页面
  ↓ props
子组件
  ↓ props
更小的子组件
```

在 React 中，父组件通过 props 把数据传给子组件。

子组件不能直接修改父组件里的状态。

如果子组件需要触发修改，就让父组件把函数也通过 props 传进去。

例如：

```tsx
<AccountForm onNameChange={setName} />
```

当输入框变化时，`AccountForm` 调用：

```tsx
onNameChange(event.target.value)
```

最终还是父组件的 `setName` 在更新状态。

## 十四、props 数据流为什么重要

理解 props 数据流很重要。

因为后面的项目会越来越复杂。

例如仪表盘可能会有：

```txt
DashboardPage
  ├── SummaryCards
  ├── AccountOverview
  ├── TransactionList
  └── GoalProgress
```

AI 对话页可能会有：

```txt
ChatPage
  ├── MessageList
  ├── ChatInput
  └── CalculationPanel
```

CSV 导入页可能会有：

```txt
ImportPage
  ├── UploadBox
  ├── PreviewTable
  └── ImportSteps
```

这些页面都会重复一个模式：

```txt
页面准备数据
  ↓
通过 props 传给组件
  ↓
组件负责展示
  ↓
用户操作调用回调函数
  ↓
页面更新状态
```

如果这个模式理解清楚，后面接 API 也会容易很多。

## 十五、复盘状态

阶段二里，我们用到了几种状态。

### 1. 数据状态

例如：

```tsx
const [accounts, setAccounts] = useState<Account[]>(initialAccounts);
```

它保存页面要展示的数据。

后面接 API 后，`accounts` 可能会从服务器返回。

### 2. 表单状态

例如：

```tsx
const [name, setName] = useState("");
const [type, setType] = useState<Account["type"]>("bank");
const [balance, setBalance] = useState("");
```

它保存用户正在输入的内容。

表单状态通常只在当前页面或当前表单组件内使用。

### 3. 错误状态

例如：

```tsx
const [error, setError] = useState("");
```

它保存当前错误提示。

错误可能来自：

- 用户输入不合法。
- API 请求失败。
- 数据格式错误。
- 数据库写入失败。

### 4. 加载状态

例如：

```tsx
const [isSubmitting, setIsSubmitting] = useState(false);
```

它表示当前是否正在处理某个操作。

后面接 API 时会更常用。

例如：

```txt
点击提交
  ↓
isSubmitting = true
  ↓
发送 POST 请求
  ↓
请求完成
  ↓
isSubmitting = false
```

## 十六、复盘 empty、error、loading

一个可用的页面不能只考虑“有数据且正常”的情况。

至少要考虑三种基础状态。

### 1. empty

没有数据时显示。

例如账户列表为空：

```tsx
if (accounts.length === 0) {
  return <EmptyAccounts />;
}
```

空状态要告诉用户：

- 当前没有什么。
- 下一步应该做什么。

### 2. error

发生错误时显示。

例如表单输入非法：

```tsx
{error && <ErrorMessage message={error} />}
```

错误提示要具体。

不推荐：

```txt
错误
```

推荐：

```txt
请输入合法的账户余额。
```

### 3. loading

正在等待时显示。

例如提交按钮：

```tsx
<button disabled={isSubmitting}>
  {isSubmitting ? "提交中..." : "新增账户"}
</button>
```

loading 状态的作用是：

- 告诉用户操作正在进行。
- 防止用户重复提交。
- 避免页面看起来没反应。

## 十七、假数据未来如何替换成 API 数据

当前阶段页面使用假数据：

```tsx
import { initialAccounts } from "@/lib/mock-data";

const [accounts, setAccounts] = useState<Account[]>(initialAccounts);
```

后面接入 API 后，数据流会变成：

```txt
页面加载
  ↓
请求 GET /api/accounts
  ↓
后端读取数据库
  ↓
返回账户 JSON
  ↓
前端 setAccounts
  ↓
AccountList 重新渲染
```

也就是：

```txt
假数据数组
```

会逐渐替换为：

```txt
API 返回的数据
```

但是组件不一定需要大改。

因为 `AccountList` 只关心：

```tsx
accounts: Account[];
```

不关心这些账户来自：

- 假数据。
- API。
- 数据库。
- CSV 导入。

这就是组件拆分的价值。

阶段二解决的是前端基础：

```txt

```

阶段三会开始解决后端数据管理：


```txt

  ↓

  ↓

  ↓
```

如果前端结构清楚，后面接 API 时只需要替换数据来源。

如果前端结构混乱，接 API 时会很痛苦。

## 十九、常见错误

### 1. 组件拆得太细

不是所有东西都要立刻拆组件。

例如一个只出现一次、只有两三行的结构，可以先留在页面里。

更适合拆组件的情况：

- 代码比较长。
- 多个页面重复使用。
- 职责非常明确。
- 有独立的 props 输入。

### 2. 组件做太多事

例如 `AccountCard` 不应该负责新增账户。

它只应该展示单个账户。

如果组件职责不清楚，后面会难维护。

### 3. 类型到处复制

如果多个文件都写了一份 `Account` 类型，后面字段变化时很容易漏改。

更好的方式是放在：

```txt
types/finance.ts
```

### 4. 子组件直接改父组件数据

React 里数据通常从父组件流向子组件。

子组件如果要触发修改，应该调用父组件传入的函数。

不要试图在子组件里直接改父组件状态。

### 5. 忘记空状态和错误状态

一个页面不能只在“有数据且正常”时可用。

至少要考虑：

- 没数据怎么办？
- 输入错了怎么办？
- 请求中怎么办？
- 请求失败怎么办？
